## 一图看懂本篇流程


模块化区块链像把餐厅分成点餐、厨房、收银和配送团队。不同层各自负责执行、共识、数据可用性或结算。

> **怎么读这张图：**从左向右看，先确认输入是什么，再看系统如何检查和处理，最后看结果如何保存或验证。图中是帮助理解的简化流程，协议细节仍以本篇后续说明和官方规范为准。


例如，一家平台把订单撮合、数据保存和最终结算分配给不同服务。模块化能让各部分独立扩展，但接口和数据可用性必须提前设计好。

## 二、代码运行与验证记录

三个程序均为独立 Go `main`，只使用标准库。已在 Go 1.27.3、Linux amd64 环境执行，正常路径与正文列出的拒绝条件均得到预期结果。

```bash
go run code/ch06/bridge_certificate/main.go
go run code/ch06/ibc_commitment/main.go
go run code/ch06/modular_batch/main.go
```

| 程序 | 已核对结果 | 未实现的系统层 |
|---|---|---|
| `bridge_certificate` | 阈值、去重、域、篡改、防重放与溢出原子性 | 源链最终性、真实托管、委员会轮换、多机一致性 |
| `ibc_commitment` | 固定版本包承诺和确认承诺，键路径变化 | IBC 客户端、完整证明与包状态机 |
| `modular_batch` | 批次承诺、顺序、nonce、新根与缺数据拒绝 | 交易签名、DA 协议、零知识证明、争议游戏 |

配套压缩包提供可直接运行的源码及实际输出。独立下载本 Markdown 也包含全部代码，不依赖其他笔记才能理解其输入与边界。

### 3.1 与密码学教材怎样衔接

| 教材 | 本讲适合回看的主题 | 本次查阅范围 |
|---|---|---|
| Katz、Lindell：*Introduction to Modern Cryptography* | 形式化安全定义、哈希、数字签名、协议组合的前提 | 作者页面、公开第三版目录和前言；未取得完整付费正文 |
| Paar、Pelzl、Güneysu：*Understanding Cryptography* 第2版 | 工程中的密钥、签名、认证与实际参数 | Springer 出版页和公开目录；中文译本应按手头版本对照 |
| 《深入浅出密码学》 | 对称/非对称密码与工程应用的基础复习 | 按对应英文教材系列定位，不把知乎搜索页视作教材正文 |
| 《现代密码学》 | 密码学安全目标与协议基础 | 书名未给作者版次；杨波第五版出版社页面仅列为候选 |

教程应帮助理解密码学原语，再回到完整系统的信任、状态和消息流程。跨链与模块化架构的具体规则主要依据下列项目规范，不能从密码学教材的章节标题推断某个产品已经实现某项功能。

### 3.3 主要技术来源

- [R1] [Hyperledger Fabric：Introduction](https://hyperledger-fabric.readthedocs.io/en/latest/whatis.html)：许可制、身份和企业账本背景。
- [R2] [Go crypto/cipher](https://pkg.go.dev/crypto/cipher)：认证加密接口；本讲只说明隐私边界。
- [R3] [Fabric：Transaction Flow](https://hyperledger-fabric.readthedocs.io/en/latest/txflow.html)：模拟执行、背书、排序和提交检查。
- [R4] [Fabric：The Ordering Service](https://hyperledger-fabric.readthedocs.io/en/latest/orderer/ordering_service.html)：排序角色与身份；历史和现行实现应按版本阅读。
- [R5] [Fabric：Private data](https://hyperledger-fabric.readthedocs.io/en/latest/private-data/private-data.html)：私有集合和公开哈希。
- [R6] [Bitcoin Developer Reference：Block Chain](https://developer.bitcoin.org/reference/block_chain.html)：区块规则、工作量与发行约束。
- [R7] [Ethereum：Gasper](https://ethereum.org/en/developers/docs/consensus-mechanisms/pos/gasper/)：分叉选择与检查点最终性。
- [R8] [Ethereum：Bridges](https://ethereum.org/en/developers/docs/bridges/)：跨链模式与信任分类。
- [R9] [IBC ICS-002：Client Semantics](https://github.com/cosmos/ibc/blob/main/spec/core/ics-002-client-semantics/README.md)：客户端接口及可信状态。
- [R10] [IBC ICS-004：Channel and Packet Semantics](https://github.com/cosmos/ibc/blob/main/spec/core/ics-004-channel-and-packet-semantics/README.md)：包、确认、接收和超时。
- [R11] [IBC ICS-020：Fungible Token Transfer](https://github.com/cosmos/ibc/blob/main/spec/app/ics-020-fungible-token-transfer/README.md)：资产来源、托管、铸造及返回。
- [R12] [IBC-Go 官方介绍](https://docs.cosmos.network/ibc/latest/intro)：Classic 与 v2 的版本关系。
- [R13] [ibc-go v8.7.0 `packet.go`](https://github.com/cosmos/ibc-go/blob/v8.7.0/modules/core/04-channel/types/packet.go)：`CommitPacket` 和 `CommitAcknowledgement`；本次已读取该固定版本原始代码。
- [R14] [EIP-155](https://eips.ethereum.org/EIPS/eip-155)：交易域中的链标识与重放保护。
- [R15] [EIP-712](https://eips.ethereum.org/EIPS/eip-712)：结构化签名与域分隔。
- [R16] [Solidity ABI 规范](https://docs.soliditylang.org/en/v0.8.30/abi-spec.html)：类型编码与紧凑编码歧义。
- [R17] [Cosmos 官方开发文档](https://docs.cosmos.network/)：SDK、CometBFT 与 IBC 的项目入口。
- [R18] [Ethereum：Data availability](https://ethereum.org/en/developers/docs/data-availability/)：数据可用性问题。
- [R19] [Celestia：DA FAQ](https://docs.celestia.org/learn/celestia-101/data-availability-faq/) 与 [交易生命周期](https://docs.celestia.org/learn/celestia-101/transaction-lifecycle/)：DAS、编码和恢复假设。
- [R20] [OP Stack：L2 Chain Derivation](https://specs.optimism.io/protocol/derivation.html)：从 L1 数据推导 L2 输入的具体实例。
- [R21] [OP Stack：Fault proofs explainer](https://docs.optimism.io/op-stack/fault-proofs/explainer)：声明、挑战与验证流程。
- [R22] [Ethereum：ZK-rollups](https://ethereum.org/en/developers/docs/scaling/zk-rollups/)：有效性验证与数据恢复。
- [R23] [EIP-4844](https://eips.ethereum.org/EIPS/eip-4844)：blob 交易、版本化哈希、验证接口与保留窗口背景。
- [R24] [EIP-7691](https://eips.ethereum.org/EIPS/eip-7691)：Pectra 阶段 blob 参数改变。
- [R25] [Go crypto/ed25519](https://pkg.go.dev/crypto/ed25519)、[crypto/sha256](https://pkg.go.dev/crypto/sha256)：本讲实际使用的标准库。
