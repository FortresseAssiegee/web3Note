### 1.1 本讲的学习目标

假设要记录一周七天的访问量，每天正好对应一个位置，可以考虑用 `[7]int`；如果要不断接收一批数量事先未知的记录，更适合用 `[]Record`。前者直接表示固定数量的元素，后者通过一个切片值描述底层数组中的一段范围。两者的区别会影响赋值、传参、追加、复制和数据共享。[官方依据：Array types](https://go.dev/ref/spec#Array_types)、[Slice types](https://go.dev/ref/spec#Slice_types)。

学习这一讲的目标，不只是能写出数组和切片字面量，而是能够回答下面的问题。

| 遇到的任务 | 需要理解的机制 | 主要位置 |
| --- | --- | --- |
| 保存固定长度的数据 | 长度属于数组类型、元素零值、数组赋值复制 | 第二章 2.1—2.4 |
| 遍历或交给函数处理 | 索引、range 元素副本、参数传值 | 第二章 2.5—2.6；第三章 3.4、3.7 |
| 保存二维或分组数据 | 嵌套数组与切片的组织方式 | 第二章 2.7—2.9 |
| 从现有数据中取一个区间 | 切片起点、长度、容量和共享底层数组 | 第三章 3.1—3.5 |
| 追加、删除、筛选和排序 | append 的返回值、原地修改、旧引用和复制 | 第三章 3.6—3.10 |
| 向外部接口返回“空结果” | nil 与非 nil 空切片、JSON 与比较语义 | 第三章 3.11.2 |

## 二、数组与数组使用

数组适合表达“数量已经确定的一组同类型数据”，例如一个点的三个坐标、一周七天的计数或一个固定长度的摘要。理解数组时，先抓住三个事实：**长度属于类型；数组变量表示整组元素；赋值和传参会复制数组值**。后面学习切片时，会看到切片如何在数组之上提供可改变长度的访问方式。

本章代码依据 Go 官方规范重新组织为完整程序。涉及官方文档中的写法时，会指出对应来源；所有 `A-xx` 示例彼此独立，统一按 Go 1.27.3 工具链与 `go 1.27.0` 模块语言设置组织。

<a id="section-2-1"></a>

### 2.1 定义与特点

数组类型写成 `[N]T`，其中 `N` 是长度，`T` 是每个元素的类型。`[3]int` 表示三个整数，合法索引为 `0、1、2`。长度必须是可以由 `int` 表示的非负常量；可以写常量表达式，例如 `[2*3]int`，但不能把运行时读入的变量直接放到数组长度位置。

长度本身参与类型判定，因此 `[3]int` 和 `[4]int` 是不同类型；即使都存储整数，也不能直接相互赋值。数组的长度不会因为修改元素、排序或把元素设为零而改变。`[0]int` 则是合法的零长度数组，只是其中没有任何可索引元素。[官方依据：Array types](https://go.dev/ref/spec#Array_types)、[Type identity](https://go.dev/ref/spec#Type_identity)。

**示例 A-01：数组的零值与固定长度。**

```go
// 运行示例：A-01
package main

import "fmt"

func main() {
	var scores [3]int
	var flags [2]bool
	var empty [0]int

	fmt.Println(scores)
	fmt.Println(flags)
	fmt.Println(len(scores), len(empty))
	fmt.Printf("%T %T\n", scores, empty)
}
```

输出：

```text
[0 0 0]
[false false]
3 0
[3]int [0]int
```

声明数组后，所有元素都已经存在，并具有元素类型的零值。整数元素为 `0`，布尔元素为 `false`，字符串元素为 `""`，指针元素为 `nil`。因此 `var scores [3]int` 可以立即访问 `scores[0]`，无需先调用 `make`。

数组本身没有“未初始化时为 nil”的状态；`var p *[3]int` 中为 nil 的是指针 `p`，与一个零值数组是两种不同情况。数组的某些元素可以是 nil，例如 `[3]*int` 的三个指针零值都为 nil，但整个数组值仍然存在。

| 需求 | 数组是否适合 | 原因 |
| --- | --- | --- |
| 固定三个坐标 | 适合，如 `[3]float64` | 数量是数据含义的一部分 |
| 固定长度摘要 | 适合，如 `[32]byte` | 长度可以体现在类型中 |
| 数量随调用方输入增长的列表 | 通常使用切片 | 不需要为每一种长度声明不同数组类型 |
| 固定容量缓冲区，再记录已用数量 | 可以使用数组与计数变量 | 物理长度固定，逻辑使用范围另行维护 |

标准库 [`sha256.Sum256`](https://pkg.go.dev/crypto/sha256#Sum256) 返回 `[32]byte`，就是通过返回类型表达结果长度固定的例子。这里讨论的是数组如何建模固定大小数据，不涉及摘要算法本身。

<a id="section-2-2"></a>

### 2.2 语法

数组常见的声明与初始化形式如下。表中的代码是语法片段，需放在适当的包或函数上下文中。

| 写法 | 含义 |
| --- | --- |
| `var a [3]int` | 三个元素，全部使用零值 |
| `a := [3]int{1, 2, 3}` | 显式写长度与三个元素 |
| `a := [5]int{1, 2}` | 前两个元素指定值，其余为零 |
| `a := [...]int{1, 2, 3}` | 编译器根据字面量推断长度为 3 |
| `a := [5]int{2: 9}` | 只指定索引 2 的元素，其余为零 |

**示例 A-02：部分初始化、索引初始化和长度推断。** 参考官方规范中数组复合字面量的规则，将几种形式放在一起比较。

```go
// 运行示例：A-02
package main

import "fmt"

func main() {
	partial := [4]int{7, 8}
	indexed := [6]int{1: 10, 20, 4: 40}
	inferred := [...]int{2: 20, 5: 50}
	slice := []int{7, 8}

	fmt.Println(partial)
	fmt.Println(indexed)
	fmt.Println(inferred, len(inferred))
	fmt.Printf("%T %T\n", inferred, slice)
}
```

输出：

```text
[7 8 0 0]
[0 10 20 0 40 0]
[0 0 20 0 0 50] 6
[6]int []int
```

在 `indexed` 中，`1: 10` 把索引定位到 1；紧随其后的未带索引元素 `20` 使用上一个索引加一，即索引 2。`inferred` 的最高显式索引为 5，因此长度为 `5+1=6`，不是字面量里写出的条目数量 2。

`[...]int{...}` 创建的仍然是数组；省略具体数字只是让编译器在编译时推断长度。`[]int{...}` 创建的才是切片，两者不能仅凭大括号里的元素相同就混为一谈。`...` 用在这里是数组字面量的特殊形式，不能把一般类型声明写成 `var a [...]int` 而不给出对应字面量。

以下是**故意错误的局部片段，不属于可运行示例**：

```go
n := 3
var a [n]int           // 错误：n 是变量，不能作为这里的数组长度
b := [2]int{1, 2, 3}   // 错误：索引 2 超出长度 2 的范围
c := [3]int{1: 2, 1: 4} // 错误：重复指定同一索引
```

如果长度来自配置或输入，通常选择 `make([]T, n)` 创建切片；如果长度在编译时就固定，使用 `const n = 3` 则可以声明 `[n]int`。官方依据：[Composite literals](https://go.dev/ref/spec#Composite_literals)、[Array types](https://go.dev/ref/spec#Array_types)。

不要把数组的创建方式与切片混淆。`make` 用于切片、map 和 channel，不能写 `make([3]int)` 来创建数组。若需要指向一个零值数组的指针，可以写 `new([3]int)`，其结果类型为 `*[3]int`；若需要指定初值，也可以写 `&[3]int{1, 2, 3}`。这两种写法返回指针，而 `var a [3]int` 声明的是数组变量。选择哪一种，取决于后续接口需要数组值还是数组指针，不取决于数组有没有初始化。参见 [Allocation](https://go.dev/ref/spec#Allocation)、[Making slices, maps and channels](https://go.dev/ref/spec#Making_slices_maps_and_channels)。

### 2.3 访问和修改数组元素

访问语法是 `a[i]`，索引必须符合整数索引规则，并满足 `0 <= i < len(a)`。数组变量的元素可以赋值，例如 `a[1] = 9`；也可以使用 `a[1] += 2` 在原值基础上更新。下标从零开始，所以长度为 4 的数组最后一个元素是 `a[3]`。

**示例 A-03：修改元素，并对外部索引做边界检查。**

```go
// 运行示例：A-03
package main

import "fmt"

func at(a [4]int, index int) (int, bool) {
	if index < 0 || index >= len(a) {
		return 0, false
	}
	return a[index], true
}

func main() {
	values := [4]int{10, 20, 30, 40}
	values[1] = 25
	values[2] += 5
	fmt.Println(values)

	value, ok := at(values, 2)
	fmt.Println(value, ok)
	value, ok = at(values, 4)
	fmt.Println(value, ok)
	value, ok = at(values, -1)
	fmt.Println(value, ok)
}
```

输出：

```text
[10 25 35 40]
35 true
0 false
0 false
```

`at` 在真正访问数组之前检查范围，所以非法索引不会触发越界。`bool` 用来区分“合法元素的值恰好为零”和“没有访问到合法元素”，这与前一讲多返回值的设计思路一致。

常量索引如果已经能在编译时判定越界，例如对 `[4]int` 访问 `a[4]`，会编译失败；运行时索引越界则会触发 panic。不要为了演示边界检查而先执行越界访问再恢复：来自外部输入的索引，通常可以在访问前直接判断。

还要区分“数组表达式”和“可修改的数组变量”。例如函数返回 `[3]int` 后，可以读取返回值中的某个元素，但不能直接把 `makeArray()[0] = 7` 当成对一个持久变量的更新；先把返回数组赋给变量，再修改该变量更明确。数组元素的赋值需要满足可寻址等规则。[官方依据：Index expressions](https://go.dev/ref/spec#Index_expressions)、[Assignment statements](https://go.dev/ref/spec#Assignment_statements)。

### 2.4 数组的长度

`len(a)` 返回数组元素个数，`cap(a)` 对数组也返回同一个长度。这里的单位是元素数量，不是字节数：一个 `[4]uint16` 有四个元素，每个元素占两个字节，但 `len` 仍然是 4。

对普通数组变量，长度已经包含在类型中，不需要遍历元素才能得到。在满足规范条件时，`len` 或 `cap` 的结果还可以作为常量使用。不过“数组长度固定”不代表 `len` 的实参表达式永远不会执行：如果它包含需要求值的函数调用，行为会不同。

**示例 A-04：长度常量、数组指针和带调用的 len。**

```go
// 运行示例：A-04
package main

import "fmt"

func build() [3]int {
	fmt.Println("build called")
	return [3]int{1, 2, 3}
}

func main() {
	var a [3]int
	const count = len(a)
	var p *[3]int

	fmt.Println(count, len(a), cap(a))
	fmt.Println(len(p), cap(p))
	fmt.Println(len(build()))
}
```

输出：

```text
3 3 3
3 3
build called
3
```

`len(a)` 的值由 `[3]int` 确定，因此可用于常量 `count`。`p` 虽然是 nil 指针，`len(p)` 和 `cap(p)` 在这里也只需知道它指向 `[3]int`，不需要解引用实际对象。这个特例不意味着 `p[0]` 安全；后者需要访问对象，会因 nil 指针而失败。

`len(build())` 中的 `build()` 则确实执行了，所以先打印 `build called`。官方规则是：数组或数组指针实参不包含通道接收或非常量函数调用时，相关 `len/cap` 表达式是常量，实参不求值。入门阶段先理解常见写法，再用此规则解释带副作用的表达式，避免简单背成“len 数组从不执行参数”。[官方依据：Length and capacity](https://go.dev/ref/spec#Length_and_capacity)。

### 2.5 数组的遍历

常见方式有下标循环 `for i := 0; i < len(a); i++`、只取索引的 `for i := range a`，以及同时取得索引和元素值的 `for i, value := range a`。需要修改原数组元素时，直接使用 `a[i]`；`range` 产生的第二个值是赋给迭代变量的元素值，不是原元素的别名。

**示例 A-05：修改迭代变量与修改原元素。**

```go
// 运行示例：A-05
package main

import "fmt"

func main() {
	a := [3]int{2, 4, 6}
	sum := 0
	for _, value := range a {
		sum += value
		value++
		fmt.Println("local", value)
	}
	fmt.Println("sum", sum)
	fmt.Println("original", a)

	for i := range a {
		a[i]++
	}
	fmt.Println("updated", a)
}
```

输出：

```text
local 3
local 5
local 7
sum 12
original [2 4 6]
updated [3 5 7]
```

第一次循环中的 `value++` 只修改本次迭代的变量，所以原数组保持不变。第二次循环通过索引写入数组元素，数组才发生变化。Go 1.22 对 `:=` 声明的迭代变量采用逐次迭代的新变量语义，但这没有把 `value` 变成数组元素的引用；要取得元素地址，使用 `&a[i]`，不要把 `&value` 当作同一个地址。

<a id="heading-013"></a>

#### 遍历期间修改数组：先看 range 表达式是什么

**示例 A-06：数组值遍历与数组指针遍历。** 依据官方规范中 range 表达式在循环前求值及数组值复制的规则编写。

```go
// 运行示例：A-06
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3}
	for i, value := range a {
		if i == 0 {
			a[1] = 20
		}
		fmt.Println("array", i, value, a[i])
	}

	b := [3]int{1, 2, 3}
	for i, value := range &b {
		if i == 0 {
			b[1] = 20
		}
		fmt.Println("pointer", i, value, b[i])
	}
}
```

输出：

```text
array 0 1 1
array 1 2 20
array 2 3 3
pointer 0 1 1
pointer 1 20 20
pointer 2 3 3
```

第一组使用数组值作为 range 表达式，可以按“先保存一份用于遍历的数组值”理解：后来对原变量 `a[1]` 的写入，影响直接读取的 `a[i]`，但不改变保存值中索引 1 的整数 `2`。这描述可观察语义，并不要求编译器一定以某种固定方式在内存中额外分配一份数组。

第二组保存的是指向 `b` 的指针，后续迭代从它指向的数组取得元素；索引 1 对应的元素在轮到它之前已改为 `20`，所以第二个值也是 `20`。元素值在交给本次迭代变量时依然会复制，指针遍历并未取消这一点。

不要把第一组概括为“所有数组 range 都完整复制数组”。例如 `for i := range a` 只需要索引，在符合 `len(a)` 为常量等条件时，range 表达式甚至不求值。若循环体每次显式读取 `a[i]`，就读取当前原数组的元素。实际代码通常应避免在遍历时引入不必要的状态变化；确实需要时，明确选择要读取的那份数据。[官方依据：For range](https://go.dev/ref/spec#For_range)、[Effective Go：Arrays](https://go.dev/doc/effective_go#arrays)、[Go 1.22 语言变化](https://go.dev/doc/go1.22#language)。

### 2.6 数组作为函数参数

形参类型是 `[N]T` 时，传入的是整个数组值的副本。形参类型是 `*[N]T` 时，复制的是指针，函数可以经由这个指针访问调用方数组。形参类型是 `[]T` 时，复制的是切片值，它可以与调用方数组共享元素。三种写法都遵守值传递，区别在于被复制的值包含什么。

**示例 A-07：同一组元素，三种参数类型。** 在 [Effective Go 的数组参数说明](https://go.dev/doc/effective_go#arrays) 基础上编写修改对照。

```go
// 运行示例：A-07
package main

import "fmt"

func changeValue(a [3]int) {
	a[0] = 99
}

func changePointer(a *[3]int) {
	a[0] = 88
}

func changeSlice(s []int) {
	s[1] = 77
}

func main() {
	a := [3]int{1, 2, 3}
	changeValue(a)
	fmt.Println(a)
	changePointer(&a)
	fmt.Println(a)
	changeSlice(a[:])
	fmt.Println(a)
}
```

输出：

```text
[1 2 3]
[88 2 3]
[88 77 3]
```

`changeValue` 中改动的是副本；`changePointer` 中的 `a[0]` 对应指针所指数组的元素，等价于通过 `(*a)[0]` 访问；`a[:]` 则创建覆盖整个数组的切片，`changeSlice` 通过共享底层数组修改索引 1。两种共享写法并不自动提供并发同步，也不隐含“只读”限制。

| 参数形式 | 长度约束 | 是否可通过该参数修改调用方元素 | 适合的接口含义 |
| --- | --- | --- | --- |
| `[3]int` | 固定 3 个元素 | 普通整数元素不受副本修改影响 | 接收一个固定大小的值 |
| `*[3]int` | 指向固定 3 个元素的数组 | 可以，前提是指针非 nil | 明确操作固定大小对象 |
| `[]int` | 长度由切片值描述 | 可以，访问范围内的元素可能共享 | 处理任意长度的序列 |

这里说“整数元素”是有意限定：如果数组元素本身是指针、切片或 map，复制这些元素后仍可能共享它们引用的对象，见 2.9。

<a id="heading-015"></a>

#### 通过返回数组得到一份变换后的值

**示例 A-08：输入保留原状，返回修改后的数组。**

```go
// 运行示例：A-08
package main

import "fmt"

func clampNegative(a [3]int) [3]int {
	for i := range a {
		if a[i] < 0 {
			a[i] = 0
		}
	}
	return a
}

func main() {
	original := [3]int{-3, 2, -1}
	changed := clampNegative(original)
	fmt.Println(original)
	fmt.Println(changed)
}
```

输出：

```text
[-3 2 -1]
[0 2 0]
```

调用过程是：复制三个整数到参数 `a`，修改本次调用的参数数组，再返回结果。调用方明确把结果放入 `changed`；如果希望更新原变量，可以写 `original = clampNegative(original)`。长度进入函数签名意味着不能直接传 `[4]int`；需要处理多种长度时，切片接口通常更自然。

大数组按值传递在语义上涉及元素复制，但不能只凭语法断定某次调用实际产生了多少次内存复制或堆分配，编译器可能进行优化。应先按数据共享需求选择接口，再对真正重要的性能问题测量。[官方依据：Calls](https://go.dev/ref/spec#Calls)、[Return statements](https://go.dev/ref/spec#Return_statements)、[FAQ：参数传递](https://go.dev/doc/faq#pass_by_value)。

### 2.7 多维数组

Go 的数组类型本身是一维的，但元素可以继续是数组。`[2][3]int` 的含义是：外层有两个元素，每个元素的类型为 `[3]int`。把外层元素称为“行”以后，就得到两行三列的直观理解；`m[i][j]` 先选第 `i` 行，再选这一行的第 `j` 个整数。

长度按层决定：`len(m)` 是 2，`len(m[0])` 是 3。`[2][3]int` 与 `[3][2]int` 的结构不同，即使都包含六个整数，也不是同一种类型。行和列只是程序对两层索引的解释，语言不会自动把它们当成数学矩阵并提供矩阵运算。

**示例 A-09：二维数组、逐行统计与行的复制。** 参考官方多维数组组合方式，用小数字演示。

```go
// 运行示例：A-09
package main

import "fmt"

func main() {
	matrix := [2][3]int{
		{1, 2, 3},
		{4, 5, 6},
	}
	var rowSums [2]int
	for i := range matrix {
		for j := range matrix[i] {
			rowSums[i] += matrix[i][j]
		}
	}
	fmt.Println(len(matrix), len(matrix[0]))
	fmt.Println(rowSums)
	fmt.Printf("%T\n", matrix[0])

	row := matrix[0]
	row[0] = 99
	fmt.Println(row)
	fmt.Println(matrix[0])
}
```

输出：

```text
2 3
[6 15]
[3]int
[99 2 3]
[1 2 3]
```

两层循环分别负责选择行与列，第一行相加得到 `1+2+3=6`，第二行得到 `4+5+6=15`。`matrix[0]` 的类型是一个完整的 `[3]int`，所以 `row := matrix[0]` 复制这一行；修改 `row[0]` 不会改动原矩阵。要修改原矩阵，可以直接写 `matrix[0][0] = 99`，或者明确取这一行的地址。

初始化中的内层 `{1, 2, 3}` 省略了已可推断的 `[3]int` 类型，展开写法是 `[3]int{1, 2, 3}`。外层可以在字面量中使用 `[...]` 推断行数，例如 `[...][3]int{{1, 2, 3}, {4, 5, 6}}`，其类型是 `[2][3]int`。每行仍须符合相同的 `[3]int` 类型。

部分初始化也按层生效：`[2][3]int{{1}, {2, 3}}` 的第一行是 `[1 0 0]`，第二行是 `[2 3 0]`。这表示元素已经存在但取零值，并非第一行只有一个元素、第二行只有两个元素。把二维数组作为函数参数时，两层长度同样进入类型；形参 `[2][3]int` 按值接收完整六个整数。若要让函数修改调用方矩阵，可以使用 `*[2][3]int`，仍须按前一节的共享规则理解。

如果每行需要不同长度，应考虑 `[][]T` 等结构。那是切片的切片，每一行分别由切片描述；它不能直接套用一个固定二维数组的形状与内存布局结论。[官方依据：Array types](https://go.dev/ref/spec#Array_types)、[Composite literals](https://go.dev/ref/spec#Composite_literals)、[Effective Go：Two-dimensional slices](https://go.dev/doc/effective_go#two_dimensional_slices)。

### 2.8 数组的内存布局

数组值包含按索引顺序排列的元素。理解布局时，要看**元素值本身占用什么**：`[4]uint16` 连续存放四个 `uint16`；`[4]*Node` 存放四个指针值，而四个指针指向的 `Node` 对象不因此变成连续存放；`[4]string` 存放字符串值，也不能把它理解成把四段字符串的所有字符拼接起来。

官方博客 [Go Slices: usage and internals](https://go.dev/blog/slices-intro) 用顺序排列的整数说明数组表示。对于二维数组，内层数组本身就是外层元素，因此可以按“第 0 行的全部元素，然后第 1 行的全部元素”理解其排列。这样的描述来自数组嵌套关系，并非由一个额外的“行指针数组”来组织。

**示例 A-10：用固定宽度元素观察数组的字节大小。**

```go
// 运行示例：A-10
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	var item uint16
	var values [4]uint16
	var matrix [2][3]uint16

	fmt.Println(unsafe.Sizeof(item))
	fmt.Println(unsafe.Sizeof(values))
	fmt.Println(unsafe.Sizeof(matrix))
	fmt.Println(unsafe.Alignof(values) == unsafe.Alignof(item))
}
```

输出：

```text
2
8
12
true
```

`unsafe.Sizeof` 用于查询一个值本身的字节大小，不递归统计它引用的其他对象。本例只查询大小与对齐关系，没有做地址转换或任意内存访问。`uint16` 的大小按规范为两个字节，因此四个元素为八字节，两行三列为十二字节。数组的对齐要求与其元素类型一致，最后一行比较的是这个关系，不把对齐值写死为某个数字。[官方依据：unsafe.Sizeof](https://pkg.go.dev/unsafe#Sizeof)、[Size and alignment guarantees](https://go.dev/ref/spec#Size_and_alignment_guarantees)。

以本例 `[2][3]uint16` 为例，元素 `matrix[i][j]` 对应的元素序号是 `i*3+j`，相对数组起点的字节偏移可按 `(i*3+j)*2` 理解。因此 `matrix[1][2]` 是从起点算起第六个元素，前面有五个元素，对应偏移 10 字节。这个计算是在解释本例布局，日常 Go 代码仍直接使用下标访问，无须自己计算地址。

还需区分以下层次：

- **元素的内部布局。** 元素若为结构体，可能包含为字段对齐插入的填充字节；数组不会把这些结构体字段重新打包。不能用“所有字段大小相加”代替元素的实际大小。
- **元素所引用的数据。** 指针、切片、字符串、map 等值可能关联其他存储，`Sizeof` 不会自动把这些存储也加进去。
- **数组所在的位置。** “元素连续”描述对象内部布局，不表示它必定放在栈上。数组可以是局部变量、全局变量、其他对象的一部分，也可能因生命周期等原因被分配到堆上。
- **零大小的特殊情况。** `[0]T` 或全部由零大小元素组成的数组大小可以为零；不同的零大小变量可能具有相同地址，不能沿用普通非零大小元素的地址直觉。

Go 会维持仍可访问对象所需的生命周期。返回局部数组的地址或返回引用它的切片是合法的；具体分配位置属于实现与优化问题，不应根据“写在函数里”直接下结论。参见 [FAQ：栈还是堆](https://go.dev/doc/faq#stack_or_heap)。

内存布局也不等于数据交换格式。把一个整数数组发送到文件或网络时，需要另外决定整数编码与字节顺序，不能因为本机元素连续就假设接收方可以直接照搬内存解释。同样，`len` 解决“有多少个元素”，`Sizeof` 解决“这个值本身占多少字节”，两者回答的是不同问题。

### 2.9 组合与嵌套数组

多维数组是“元素仍是数组”的一种组合。实际程序还可能使用“结构体里有数组”“数组里有结构体”“数组里有指针”等形式。选择时先问固定的数量描述哪一层，再把这个约束放在相应类型中。

**示例 A-11：数组中的结构体，再包含固定长度数组字段。**

```go
// 运行示例：A-11
package main

import "fmt"

type Pixel struct {
	Position [2]int
	Color    [3]uint8
}

func main() {
	frame := [2]Pixel{
		{Position: [2]int{0, 0}, Color: [3]uint8{10, 20, 30}},
		{Position: [2]int{1, 0}, Color: [3]uint8{40, 50, 60}},
	}
	changed := frame
	changed[0].Color[0] = 255

	fmt.Println(frame[0].Position)
	fmt.Println(frame[0].Color)
	fmt.Println(changed[0].Color)
}
```

输出：

```text
[0 0]
[10 20 30]
[255 20 30]
```

`frame` 固定包含两个 `Pixel`；每个像素的 `Position` 固定包含两个整数，`Color` 固定包含三个 `uint8`。赋值 `changed := frame` 复制整个外层数组，并依次复制结构体及其中数组字段的值。本例所有字段最终都是普通数字，所以副本修改不会影响原值。

<a id="heading-019"></a>

#### 数组复制不等于递归复制所有引用对象

**示例 A-12：数组元素是指针时，共享的是指向的对象。**

```go
// 运行示例：A-12
package main

import "fmt"

func main() {
	n := 10
	original := [2]*int{&n, nil}
	changed := original
	*changed[0] = 20
	fmt.Println(n, *original[0], *changed[0])

	other := 30
	changed[0] = &other
	fmt.Println(*original[0], *changed[0])
	fmt.Printf("%T %T\n", original, &[2]int{})
}
```

输出：

```text
20 20 20
20 30
[2]*int *[2]int
```

复制后，两份数组的第一个元素都保存指向 `n` 的指针，因此 `*changed[0] = 20` 修改同一个整数。随后 `changed[0] = &other` 改的是副本数组的指针元素，原数组的对应元素仍指向 `n`。看赋值左边有几层索引与解引用，可以准确找到真正改变的对象。

| 类型 | 应怎样读 | 固定长度约束在哪里 |
| --- | --- | --- |
| `[2][3]int` | 含两个 `[3]int` 的数组 | 两层都固定 |
| `[2]*int` | 含两个整数指针的数组 | 指针数量固定为 2 |
| `*[2]int` | 指向一个两元素整数数组的指针 | 被指向数组的长度固定为 2 |
| `[2][]int` | 含两个整数切片的数组 | 外层固定，内层长度由各自切片值决定 |
| `[][2]int` | 元素为两整数数组的切片 | 外层长度可变，内层每项固定为 2 |

同理，数组元素若是切片或 map，赋值只复制相应值，不会递归复制底层数组或映射数据。若业务要求独立副本，需按每一层共享关系显式复制。`[2][]int` 的两项切片也不必有相同长度，不能把它当作 `[2][3]int` 那样的固定矩形。

组合类型还必须有可确定的大小。直接写 `type Node [2]Node` 会无限嵌套而无法形成合法类型；`type Node [2]*Node` 则通过指针间接关联其他节点，可以定义。这个限制有助于区分“把值本身放进对象”和“保存通向另一个对象的引用”。[官方依据：Array types](https://go.dev/ref/spec#Array_types)、[Struct types](https://go.dev/ref/spec#Struct_types)、[Representation of values](https://go.dev/ref/spec#Representation_of_values)。

### 2.10 数组的常见操作

<a id="section-2-10-1"></a>

#### 2.10.1 复制、比较与作为 map 键

同类型数组可直接赋值来复制。若元素类型可比较，则数组也可使用 `==` 和 `!=`，比较会依次检查对应元素。数组通常适合做固定长度组合键，例如 `[2]int` 表示一个二维网格坐标。

**示例 A-13：独立的数组副本与数组键。**

```go
// 运行示例：A-13
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3}
	b := a
	fmt.Println(a == b)
	b[0] = 9
	fmt.Println(a, b, a == b)

	labels := map[[2]int]string{
		{1, 2}: "target",
	}
	fmt.Println(labels[[2]int{1, 2}])
	fmt.Println(len(labels))
}
```

输出：

```text
true
[1 2 3] [9 2 3] false
target
1
```

两份数组初始元素相同，因此比较为 true；修改副本元素后，原数组不变且比较为 false。map 查找用的是 `[2]int{1, 2}` 这个值，其两个元素与已有键相同，所以能够找到条目，并不要求它来自同一个数组变量。

“数组可比较”必须加上条件：`[2]int` 可以比较，`[2][]int` 因切片元素不可比较，不能使用 `==`，也不能作为 map 键。若元素类型是接口，则还要考虑动态值：`[1]any` 在类型上可比较，但其中装入切片等不可比较值时，比较可能触发 panic。含浮点数的数组则遵循浮点比较规则，含 `NaN` 的元素可能使值与自身比较也不相等。[官方依据：Comparison operators](https://go.dev/ref/spec#Comparison_operators)、[Map types](https://go.dev/ref/spec#Map_types)。

<a id="section-2-10-2"></a>

#### 2.10.2 查找、统计、反转与排序

数组没有自动生成的“求和”“查找”方法，但这些操作可以用遍历表达。通用的序列算法也可通过数组的切片视图调用；视图仍指向原数组，因此原地排序会修改原数组元素。

**示例 A-14：一组整数的常用操作。** 遍历部分按官方 range 规则编写，排序使用 [`slices.Sort`](https://pkg.go.dev/slices#Sort) 的官方接口。

```go
// 运行示例：A-14
package main

import (
	"fmt"
	"slices"
)

func main() {
	a := [5]int{4, 1, 3, 1, 2}
	sum := 0
	firstIndex := -1
	for i, value := range a {
		sum += value
		if value == 3 && firstIndex == -1 {
			firstIndex = i
		}
	}
	fmt.Println("sum", sum, "index", firstIndex)

	reversed := a
	for left, right := 0, len(reversed)-1; left < right; left, right = left+1, right-1 {
		reversed[left], reversed[right] = reversed[right], reversed[left]
	}
	fmt.Println("reversed", reversed)

	slices.Sort(a[:])
	fmt.Println("sorted", a)
	fmt.Println("length", len(a))
}
```

输出：

```text
sum 11 index 2
reversed [2 1 3 1 4]
sorted [1 1 2 3 4]
length 5
```

查找过程中用 `-1` 表示尚未找到，因为合法索引不会是负数。反转时，先复制数组到 `reversed`，再从两端向中间交换元素，所以原数组此时没有受反转影响。排序通过 `a[:]` 操作共享数组数据，因而最后 `a` 的内容发生改变，但长度仍然是 5。

`slices` 是 Go 1.21 加入标准库的包，本笔记的 Go 1.27.0 模块基线可使用它。它提供适用于切片的通用操作，不代表 `[5]int` 类型本身多了一个 `Sort` 方法。若希望排序结果也与输入隔离，应先复制数组，再对副本的切片视图排序。[官方依据：Go 1.21 新标准库包](https://go.dev/doc/go1.21#slices)、[Slice expressions](https://go.dev/ref/spec#Slice_expressions)。

<a id="section-2-10-3"></a>

#### 2.10.3 插入和删除：区分物理长度与逻辑数量

数组的物理长度不会改变。如果数组只使用了前面一部分元素，可以另存一个 `used` 计数，插入时写入空闲位置，删除时搬移后续元素，再调整计数。这种做法管理的是逻辑有效范围。对于一般可增长列表，使用切片通常能更直接地表达需求。

**示例 A-15：用固定数组实现最多四个整数的缓冲区。** 本例按数组、切片视图及 `copy` 规则编写；它旨在说明“数组长度固定”与“有效数据数量可变”可以同时成立。

```go
// 运行示例：A-15
package main

import "fmt"

type FixedBuffer struct {
	data [4]int
	used int
}

func (b *FixedBuffer) Push(value int) bool {
	if b.used == len(b.data) {
		return false
	}
	b.data[b.used] = value
	b.used++
	return true
}

func (b *FixedBuffer) RemoveAt(index int) bool {
	if index < 0 || index >= b.used {
		return false
	}
	copy(b.data[index:b.used-1], b.data[index+1:b.used])
	b.used--
	b.data[b.used] = 0
	return true
}

func main() {
	var b FixedBuffer
	for _, value := range [4]int{1, 2, 3, 4} {
		b.Push(value)
	}
	fmt.Println(b.data, b.used)
	fmt.Println(b.Push(5))
	fmt.Println(b.RemoveAt(1))
	fmt.Println(b.data, b.used)
	fmt.Println(b.Push(5))
	fmt.Println(b.data, b.used)
}
```

输出：

```text
[1 2 3 4] 4
false
true
[1 3 4 0] 3
true
[1 3 4 5] 4
```

缓冲区已满时，第一次 `Push(5)` 返回 false。删除索引 1 的元素后，`copy` 将后面的 `3、4` 向前搬一位；`used` 从 4 减到 3，原尾部位置清零，于是打印整个物理数组时看到 `[1 3 4 0]`。再次插入 5 成功，写入索引 3。整个过程 `len(b.data)` 始终为 4。

`copy` 的源和目标可以重叠，本例正好利用这一保证完成左移。它接收切片，所以使用了 `b.data[...:...]` 创建的视图；不能直接把两个数组值当成 `copy` 的普通切片参数。这里清零尾部能让有效范围外的状态清晰；如果元素包含指针等引用，清除不再使用的元素还与避免保留旧对象有关，切片章节会继续说明。[官方依据：Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)。

常见操作可按下面的方式选择：

| 目的 | 数组上的常见写法 | 需要注意 |
| --- | --- | --- |
| 完整复制 | `b := a` | 元素含引用时不会递归深复制对象 |
| 清零全部元素 | `a = [N]T{}` | 不改变类型或长度 |
| 逐个修改 | `for i := range a { a[i] = ... }` | 修改迭代值副本不会更新原元素 |
| 比较内容 | `a == b` | 长度和元素类型须满足类型规则，元素还须可比较 |
| 排序或调用序列函数 | 对 `a[:]` 操作 | 与原数组共享数据，会影响原数组 |
| 增加或减少有效条目 | 维护有效数量并搬移元素，或改用切片 | 数组本身不会伸缩 |

完成数组部分后，应能从类型写法判断长度约束，从赋值左侧判断修改目标，并从元素类型判断复制后是否仍有共享对象。这三点会直接用于下一章的切片、容量、复制与扩容分析。

## 三、切片和切片深入

数组适合表达“元素数量就是类型约定的一部分”；处理查询结果、读取数据、收集任务等数量可变的序列时，切片通常更方便。本章先学会创建、读取、追加、复制和截取，再讨论函数传递、使用场景与底层机制。

### 3.1 切片基本介绍

<a id="heading-026"></a>

#### 切片描述一段数据，底层数组存放元素

切片类型写作 `[]T`，其中 `T` 是元素类型。与 `[3]int` 不同，`[]int` 的类型中没有固定长度，因此同一个变量可以先表示两个整数，后来再表示五个整数。

为了理解行为，可以把一个切片值看作描述三件事的信息：从哪一个元素开始访问、当前长度是多少，以及允许重新切片到的最大长度是多少。真正的元素保存在底层数组中。这个模型用来解释程序可观察到的共享与边界，不要求我们把切片当成可自行改写内部字段的结构体。正式依据见 [Slice types](https://go.dev/ref/spec#Slice_types) 与官方博客 [Go Slices: usage and internals](https://go.dev/blog/slices-intro)。

以长度为 3 的切片为例，`len(s)` 为 3，合法索引是 `0、1、2`。重新切片可以改变一个切片值所描述的范围；追加可能得到引用新数组的切片。底层数组本身的长度不会原地变成另一个数字。

**示例 S-01：复制切片值，与复制元素是不同操作。**

```go
// 运行示例：S-01
package main

import "fmt"

func main() {
	a := []int{10, 20, 30}
	b := a
	b[0] = 99
	b = b[:2]

	fmt.Println("a:", a, len(a), cap(a))
	fmt.Println("b:", b, len(b), cap(b))
}
```

输出：

```text
a: [99 20 30] 3 3
b: [99 20] 2 3
```

执行 `b := a` 后，`a` 和 `b` 是两个变量，里面保存的切片值最初相同，它们引用同一个底层数组。`b[0] = 99` 修改共享数组的第一个元素，因此通过 `a[0]` 也能看到 `99`。随后 `b = b[:2]` 只给变量 `b` 换上长度为 2 的切片值，变量 `a` 的长度仍为 3。

| 操作 | 修改的是谁 | 另一个切片是否能观察到 |
| --- | --- | --- |
| `b[0] = 99` | 底层数组中的元素 | 引用同一元素的 `a` 能观察到 |
| `b = b[:2]` | 变量 `b` 保存的切片值 | `a` 的长度不会跟着改变 |
| `b := a` | 创建变量并复制切片值 | 不会因此复制一整份元素 |

因此，不能把切片简单记成“数组的引用”后便忽略值传递规则。切片本身是值，赋值和参数传递会复制这个值；复制后的值又可能引用相同数据。涉及函数参数时，这一区分会决定“为什么能修改元素，却不能直接替调用方更新长度”。[官方展开：The mechanics of append](https://go.dev/blog/slices)。

读代码时，可以给每个切片变量分别写一张小记录：起点对应原数组的哪个位置、当前有几个元素、最多允许扩展到几个元素。只有执行元素赋值时，才在共享数组上改数字；执行重新切片或把 append 结果赋回变量时，则先更新这个变量的记录。这个记账方式是学习模型，不是在声称 Go 程序真的维护了额外表格，它有助于把“变量变化”和“存储内容变化”分开观察。

<a id="section-3-2"></a>

### 3.2 定义切片的语法

基本声明形式是 `var s []T`。声明没有提供初值时，切片的零值为 `nil`；对它调用 `len` 和 `cap` 都得到 0。以下是语法片段，不是完整程序：

```go
var numbers []int       // 元素是 int
var names []string      // 元素是 string
var rows [][]int        // 元素是另一个 []int
var pointers []*int     // 元素是 *int
```

`[]int` 与 `[]string` 是不同类型；`[]int` 与 `[3]int` 也是不同类型。二维切片 `[][]int` 的每个元素又是切片，各行的长度可以不同，这与固定行列数的二维数组有区别。这里只先认识声明形状，实际结构和使用场景在后文展开。

**示例 S-02：没有元素，不代表切片一定为 nil。**

```go
// 运行示例：S-02
package main

import (
	"fmt"
	"slices"
)

func main() {
	var missing []int
	empty := []int{}
	values := []int{4, 8}

	fmt.Println(len(missing), cap(missing), missing == nil)
	fmt.Println(len(empty), cap(empty), empty == nil)
	fmt.Println(values)
	fmt.Println(slices.Equal(missing, empty))
	fmt.Println(slices.Equal(values, []int{4, 8}))
}
```

输出：

```text
0 0 true
0 0 false
[4 8]
true
true
```

`missing` 是 nil 切片；`empty` 是一个非 nil、长度为零的切片。二者都没有可索引元素，因此不能写 `missing[0]` 或 `empty[0]`。在只关心“有没有元素”时，应判断 `len(s) == 0`；如果接口约定用 nil 表示特殊状态，再额外判断 `s == nil`。

切片不能使用 `s1 == s2` 比较两个序列，即使它们的元素类型为 `int` 也不行。切片允许与 `nil` 比较；需要比较内容时，`slices.Equal` 按长度和对应元素判断，所以把 nil 切片与非 nil 空切片视为相等。元素类型必须满足该 API 的可比较约束；元素需要自定义判断时可用 `slices.EqualFunc`。字节切片还可以使用 `bytes.Equal`，但不要把这些 API 的内容相等语义与 nil 状态判断混在一起。

官方依据：[Slice types](https://go.dev/ref/spec#Slice_types)、[Comparison operators](https://go.dev/ref/spec#Comparison_operators)、[slices.Equal](https://pkg.go.dev/slices#Equal)、[slices.EqualFunc](https://pkg.go.dev/slices#EqualFunc)、[bytes.Equal](https://pkg.go.dev/bytes#Equal)。

### 3.3 切片的初始化和声明

<a id="section-3-3-1"></a>

#### 3.3.1 使用内置函数 make

`make([]T, length)` 创建指定长度的切片，容量等于长度；`make([]T, length, capacity)` 允许另外预留容量。元素初始化为类型 `T` 的零值。`make` 返回的是 `[]T`，不需要再解引用才能访问元素。

参数必须满足非负、可表示为 `int`、长度不大于容量等规则。编译期就能确定不合法的常量参数会被拒绝；运行时才确定的不合法参数会引发 panic。不要把为运行时数据准备空间写成任意负数，也不要只关心容量而忘记当前长度。[官方依据：Making slices, maps and channels](https://go.dev/ref/spec#Making_slices_maps_and_channels)。

**示例 S-03：已经存在的元素，与为以后追加保留的位置。**

```go
// 运行示例：S-03
package main

import "fmt"

func main() {
	ready := make([]int, 3, 5)
	ready[1] = 7
	fmt.Println(ready, len(ready), cap(ready))

	building := make([]int, 0, 5)
	fmt.Println(building, len(building), cap(building))
	building = append(building, 42)
	fmt.Println(building, len(building), cap(building))
}
```

输出：

```text
[0 7 0] 3 5
[] 0 5
[42] 1 5
```

`ready` 当前已经有 3 个元素，所以可以写入 `ready[1]`。`building` 只是预留了容量，长度为 0，开始时不能执行 `building[0] = 42`；`append` 产生长度为 1 的结果并赋回变量后，索引 0 才属于当前范围。

这两种模式对应不同的数据构造过程：已经知道结果恰好有多少项，可以先 `make` 出相应长度并按索引填入；只知道一个数量估计，需要逐项筛选或收集，常用长度 0、预留容量再追加。预留过多也会增加内存持有量，因此容量估计应服务于实际数据规模。

一个常见错误是想收集三个结果，却先写 `result := make([]int, 3)`，之后再追加 `2、4、6`。前三个零值本来已经属于切片，append 不会自动寻找并替换这些零，最终结果是 `[0 0 0 2 4 6]`，长度为 6。修正时应根据用途选择：需要按位置填入，就保留长度 3 并写 `result[i] = value`；需要追加构建，就从长度 0 开始。判断标准是“现在已经有几项”，而不是“将来预计最多需要几项”。

<a id="section-3-3-2"></a>

#### 3.3.2 使用简短声明方式

`:=` 是变量声明方式，本身不负责分配切片元素；真正决定如何构造值的是右边的表达式。下面几个局部片段都要求放在函数内：

```go
names := []string{"Go", "Gopher"} // 切片字面量
buffer := make([]byte, 4)         // make 创建四个 byte 元素
copyOfHeader := names            // 复制切片值，元素仍共享
```

切片字面量写作 `[]T{元素...}`。其中 `{}` 为空，得到的是非 nil 空切片；如果元素已经确定，字面量能直接展示内容。对比 `[...]int{2, 4, 6}`：省略号让编译器推断的是**数组长度**，结果类型为 `[3]int`；`[]int{2, 4, 6}` 才是切片，类型为 `[]int`。

字面量也支持用索引指定位置，例如片段 `s := []int{1: 20, 3: 40}` 形成 `[0 20 0 40]`，长度为 4，未指定的位置取零值。这适用于需要强调少数位置的初始化；索引规则仍由编译器检查，不能写重复的常量索引。

在包级声明变量时，使用 `var names = []string{"Go", "Gopher"}`，不能使用 `:=`。将切片传入函数或保存到结构体字段时，还应区分“声明了一个新切片变量”和“创建了独立元素存储”，S-01 已说明两者并不等价。

官方依据：[Composite literals](https://go.dev/ref/spec#Composite_literals)、[Short variable declarations](https://go.dev/ref/spec#Short_variable_declarations)。

<a id="section-3-3-3"></a>

#### 3.3.3 从数组或其他切片创建

通过 `source[low:high]` 可以选择一段连续元素，包含下界 `low`，不包含上界 `high`，结果长度为 `high-low`。这通常称为“左闭右开”区间，例如 `[1:4]` 选择原索引 `1、2、3`。新切片的索引从 0 重新开始。

**示例 S-04：数组、第一层切片与第二层切片访问同一个元素。** 根据官方规范的嵌套切片示例改编，缩小数组并增加输出。

```go
// 运行示例：S-04
package main

import "fmt"

func main() {
	a := [5]int{10, 20, 30, 40, 50}
	s := a[1:4]
	t := s[1:3]
	t[0] = 99

	fmt.Println("array:", a)
	fmt.Println("s:", s, len(s), cap(s))
	fmt.Println("t:", t, len(t), cap(t))
}
```

输出：

```text
array: [10 20 99 40 50]
s: [20 99 40] 3 4
t: [99 40] 2 3
```

`s[0]` 对应 `a[1]`；`t[0]` 对应 `s[1]`，也就是 `a[2]`。因此修改 `t[0]`，三种访问路径都能看到改变。这里没有复制数组元素，创建的是描述不同起点和长度的切片值。

从数组取得切片要求数组可寻址。常见数组变量 `a` 满足条件；直接对某些不可寻址的数组临时值执行切片操作则不合法，可以先存入局部数组变量。对数组指针切片时，语言允许按规则省略显式解引用。具体边界与容量计算在 3.5 中统一说明。

常见省略写法如下，`high` 默认是当前长度，不是容量：

| 表达式 | 等价范围 | 说明 |
| --- | --- | --- |
| `s[:3]` | `s[0:3]` | 从当前切片开头取三个元素 |
| `s[2:]` | `s[2:len(s)]` | 从索引 2 到当前末尾 |
| `s[:]` | `s[0:len(s)]` | 长度和容量保持不变，仍共享元素 |
| `s[:0]` | `s[0:0]` | 当前长度变为零，通常仍保留可重新使用的容量 |

对 nil 切片执行合法的 `s[:0]`，结果仍为 nil。缩短长度不等于清空数组中的旧元素，也不等于底层数组立刻被释放；后文会进一步讨论数据保留和内存生命周期。[官方依据：Slice expressions](https://go.dev/ref/spec#Slice_expressions)。

<a id="section-3-4"></a>

### 3.4 切片的基本操作

<a id="section-3-4-1"></a>

#### 3.4.1 访问或者修改元素

用 `s[i]` 读取或修改元素，索引必须满足 `0 <= i < len(s)`。边界由**当前长度**决定，即使底层还留有容量，也不能直接索引尚未纳入当前切片范围的位置。运行时索引越界会 panic，处理外部输入时应先验证索引。

**示例 S-05：安全读取、修改元素与取得元素地址。**

```go
// 运行示例：S-05
package main

import "fmt"

func at(values []int, index int) (int, bool) {
	if index < 0 || index >= len(values) {
		return 0, false
	}
	return values[index], true
}

func main() {
	values := []int{5, 10, 15}
	values[1] += 2
	p := &values[2]
	*p = 20
	fmt.Println(values)

	for _, index := range []int{-1, 1, 3} {
		value, ok := at(values, index)
		fmt.Println(index, value, ok)
	}
}
```

输出：

```text
[5 12 20]
-1 0 false
1 12 true
3 0 false
```

`at` 把“读到零”与“索引无效”分开表达，调用方需要检查 `ok`。访问最后一个元素使用 `len(values)-1`，前提是长度大于零；直接对空切片使用这个表达式，会得到负索引。

切片元素可取地址，因此 `p := &values[2]` 指向一个具体数组元素。若以后发生扩容，`p` 不会自动改为指向新数组的同位置元素；它仍然指向原元素。取得元素指针前后如果还会修改切片结构，就应特别明确期望引用的是哪个对象。扩容之后的指针关系在后文单独演示。

元素是什么，由 `T` 决定。`[]byte` 的一个元素是一个字节，`[]rune` 的一个元素是一个 Unicode 码点，`[]Record` 的一个元素是一份 Record 值。例如把中文字符串转换为字节切片后，按索引访问只取一个 UTF-8 编码字节，未必能独立表示一个完整汉字。切片的索引规则始终一致，变化的是元素的业务意义；不要从“都是用方括号访问”推断不同元素类型具有相同的文本语义。转换规则见 [Conversions](https://go.dev/ref/spec#Conversions)。

官方依据：[Index expressions](https://go.dev/ref/spec#Index_expressions)、[Address operators](https://go.dev/ref/spec#Address_operators)。

#### 3.4.2 切片长度和容量的获取

`len(s)` 表示当前元素数量；`cap(s)` 表示从当前起点开始，该切片通过重新切片能够扩展到的最大长度。两者计量单位都是**元素个数**，不是字节。即使元素换成较大的结构体，长度 10 仍表示十个元素。

容量不能一概解释为“从起点到底层数组末尾”：三下标切片可以主动把容量限制得更小，3.5 会演示。只看当前可见元素也无法推断容量，例如 `make([]int, 2, 10)` 与 `[]int{0, 0}` 打印出来都可能是 `[0 0]`，容量却不同。

**示例 S-06：重新切片可扩展到容量，但直接索引不能越过长度。**

```go
// 运行示例：S-06
package main

import "fmt"

func main() {
	a := [6]int{0, 10, 20, 30, 40, 50}
	s := a[1:3]
	extended := s[:4]
	empty := s[:0]

	fmt.Println("s:", s, len(s), cap(s))
	fmt.Println("extended:", extended, len(extended), cap(extended))
	fmt.Println("empty:", empty, len(empty), cap(empty))
	fmt.Println("restored:", empty[:2])
}
```

输出：

```text
s: [10 20] 2 5
extended: [10 20 30 40] 4 5
empty: [] 0 5
restored: [10 20]
```

`s` 起点对应 `a[1]`，到数组末尾还有五个元素，因此这里容量为 5。`s[:4]` 的上界 4 不超过容量，合法地形成长度为 4 的切片；原来的 `s` 本身仍只有两个元素，不能因为 `extended` 已创建，就直接访问 `s[2]`。

`empty := s[:0]` 把可见范围缩为零，但保留了起点和容量，原来的 `10、20` 没有被擦除。因此 `empty[:2]` 又能看到它们。这可用于复用缓冲区，但若业务意图是删除敏感内容或解除元素中的引用，单纯把长度改成零不够，需要按相应需求清理数据。

`len`、`cap` 是预声明内置函数，`make` 返回的切片也是普通的切片值；调用这些函数不需要导入额外包。边界规则见 [Length and capacity](https://go.dev/ref/spec#Length_and_capacity) 与 [Slice expressions](https://go.dev/ref/spec#Slice_expressions)。

#### 3.4.3 切片的遍历

遍历最常见的两种写法是普通索引循环和 `for range`。只需要值时用 `for _, value := range s`；需要修改原元素时，用索引访问 `s[i]` 更直接。

`range` 的第二个迭代值赋给一个变量，因此对于整数、普通结构体等值，修改该迭代变量不会自动写回切片元素。如果元素本身是指针或包含引用的结构体，修改副本所引用的数据又可能被外部观察到，仍需回到“复制了什么、共享了什么”来判断。

**示例 S-07：修改迭代变量，与按索引修改元素。**

```go
// 运行示例：S-07
package main

import "fmt"

func main() {
	values := []int{1, 2, 3}
	for _, value := range values {
		value *= 10
		_ = value
	}
	fmt.Println("after changing copies:", values)

	for i := range values {
		values[i] *= 10
	}
	fmt.Println("after changing elements:", values)

	sum := 0
	for _, value := range values {
		sum += value
	}
	fmt.Println("sum:", sum)
}
```

输出：

```text
after changing copies: [1 2 3]
after changing elements: [10 20 30]
sum: 60
```

第一轮循环把 `1、2、3` 分别赋给局部变量 `value`，计算结果没有写回原位置。第二轮明确以 `values[i]` 为赋值目标，所以改变的是底层数组元素。最后一轮只需读取数值，丢弃索引即可。

**示例 S-08：循环开始时确定长度，不等于预先复制所有元素。**

```go
// 运行示例：S-08
package main

import "fmt"

func main() {
	values := make([]int, 3, 6)
	copy(values, []int{1, 2, 3})

	for i, value := range values {
		if i == 0 {
			values = append(values, 4, 5)
			values[1] = 20
		}
		fmt.Println(i, value)
	}
	fmt.Println("after loop:", values)
}
```

输出：

```text
0 1
1 20
2 3
after loop: [1 20 3 4 5]
```

循环开始时，range 表达式得到长度为 3 的切片值，所以只产生三个索引。循环里变量 `values` 被更新为长度 5 的切片，不会让这次 range 自动多迭代两次。预留容量为 6，追加不需要换底层数组；下一轮读取原索引 1 时，会读到已修改的 `20`。这说明固定的是本次遍历使用的切片范围，而不是整个元素序列的不可变快照。

如果遍历中追加引发换数组，新旧切片可能不再引用同一存储，结果又要分别追踪。实际业务通常应避免在一轮遍历中同时改变输入结构：可以把待追加的结果收集到另一个切片，或者明确使用并控制普通索引循环。`for i := 0; i < len(s); i++` 每轮重新计算循环条件中的长度，与上面的 range 行为也不同。

如果使用普通索引循环，并且每一轮都继续给同一个切片追加元素，循环条件也可能随着长度增长而一直成立。需要处理“开始时已有的那一批数据”时，可以先保存 `limit := len(s)`，再使用 `i < limit`；需要持续消费新任务时，则应另外设计终止条件和容量约束。选择循环形式应表达处理范围，而不是只看哪一种写起来更短。

Go 1.22 起，使用 `:=` 声明的循环变量按迭代分别创建，这影响闭包捕获和保存变量地址；它并没有把 `value` 变成原切片元素的别名。需要元素地址时，应明确使用合法索引的 `&s[i]`。nil 切片和其他长度为零的切片都可以安全 range，循环体执行零次。

官方依据：[For statements with range clause](https://go.dev/ref/spec#For_range)、[Go 1.22 语言变化](https://go.dev/doc/go1.22#language)。

#### 3.4.4 追加元素

`append` 接收一个切片和零个或多个元素，返回追加后的切片值。常见形式包括 `s = append(s, value)`、`s = append(s, a, b)` 和 `s = append(s, other...)`。最后一种把另一个切片的元素作为可变参数提供给 append；省略 `...` 会把整个切片当成一个元素，通常造成类型不匹配。

必须使用返回值来获得更新后的长度以及可能变化的底层数组引用。最常见的写法是赋回 `s`，也可以返回给调用者或者赋给另一个变量。单独写一个丢弃结果的 `append(s, value)` 语句会被编译器拒绝；即使通过 `_ = append(...)` 刻意丢弃返回值，也不会自动更新变量 `s`。

**示例 S-09：从 nil 切片开始追加，并展开已有切片。**

```go
// 运行示例：S-09
package main

import "fmt"

func main() {
	var numbers []int
	numbers = append(numbers, 2, 4)
	extra := []int{6, 8}
	numbers = append(numbers, extra...)
	fmt.Println(numbers, len(numbers))

	text := []byte("Go")
	text = append(text, " slices"...)
	fmt.Printf("%s %d\n", text, len(text))
}
```

输出：

```text
[2 4 6 8] 4
Go slices 9
```

nil 切片可直接追加，不必先 `make` 一个长度为零的切片。`append(text, " slices"...)` 是语言为字节切片提供的特殊形式，把字符串中的字节追加进去；不能推广成任意 `[]T` 都能接收字符串。`len([]byte)` 统计的是字节元素个数，本例使用 ASCII 文本，因而字节数与可见字符数量一致。

追加时，若已有容量足够，结果复用原数组；否则，append 创建足够大的新数组，将原元素和新增元素放入其中。语言保证的是结果和存储复用条件，没有要求扩容后的容量一定恰好等于新长度，也没有规定统一的倍增数字。

**示例 S-10：两个追加结果可能修改同一个尾部位置。**

```go
// 运行示例：S-10
package main

import "fmt"

func main() {
	a := make([]int, 2, 4)
	copy(a, []int{1, 2})
	b := append(a, 3)
	c := append(a, 9)

	fmt.Println("a:", a)
	fmt.Println("b:", b)
	fmt.Println("c:", c)
	fmt.Println(len(a), len(b), len(c))
}
```

输出：

```text
a: [1 2]
b: [1 2 9]
c: [1 2 9]
2 3 3
```

第一次 append 把 `3` 写入底层索引 2，返回长度为 3 的 `b`；变量 `a` 的长度仍为 2。第二次仍以 `a` 为输入，因此再次从它的长度 2 处追加，把同一个位置改为 `9`，于是 `b[2]` 也变成 9。这里没有错误的执行顺序，也没有随机扩容行为：两次追加都能放进容量 4，按规范复用同一个数组。

如果希望让 `b` 保留自己的元素，应使用复制或者按契约限制共享，不能只换一个变量名。涉及函数返回时，常见约定是“调用者继续使用返回的切片，并停止使用可能过期的旧视图”；更具体的接口选择见后文。

官方依据：[Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)、[官方博客：The mechanics of append](https://go.dev/blog/slices)。

#### 3.4.5 切片的复制

`copy(dst, src)` 将元素从 `src` 复制到 `dst`，返回实际复制的元素数。这个数量等于两者长度的较小值，目标容量不参与这个数量的计算。`copy` 不会自动为目标扩容，也不会替调用方改变目标长度。

**示例 S-11：只预留容量，不能直接用 copy 填满。**

```go
// 运行示例：S-11
package main

import "fmt"

func main() {
	src := []int{10, 20, 30}
	dst := make([]int, 2)
	n := copy(dst, src)
	fmt.Println(n, dst)

	onlyCapacity := make([]int, 0, 3)
	n = copy(onlyCapacity, src)
	fmt.Println(n, onlyCapacity)

	full := onlyCapacity[:3]
	n = copy(full, src)
	fmt.Println(n, full)
	src[0] = 99
	fmt.Println("independent elements:", full)
}
```

输出：

```text
2 [10 20]
0 []
3 [10 20 30]
independent elements: [10 20 30]
```

第一次目标只有两个位置，因此只能复制 `10、20`。第二次目标长度为零，即使容量为三，也没有属于该切片当前范围的目标元素，所以复制数量为零。第三次先合法地扩展长度，再复制三个元素。

这里 `full` 引用的是新建的目标数组，所以后来修改 `src[0]` 不会影响它。需要独立副本时，常见做法是先 `make([]T, len(src))`，再 `copy`。如果目标长度大于源长度，超过实际复制数量的目标元素保持原值，不会自动归零。

`copy` 的源与目标切片需要满足规范的元素类型要求。不能因为单个 `string` 能赋给 `any`，就认为 `copy([]any, []string)` 也能自动逐项完成类型装箱。需要这种转换时，应显式循环。另一个特殊形式是从字符串复制到字节切片，例如局部片段 `n := copy(buf, "Go")`，若要复制全部两个字节，`buf` 的当前长度至少为 2；更短时只复制能容纳的部分，并返回实际复制数。

**示例 S-12：同一底层数组中重叠复制是合法操作。** 参考官方博客的移动元素思路，分别观察向右与向左移动。

```go
// 运行示例：S-12
package main

import "fmt"

func main() {
	right := []int{1, 2, 3, 4, 5}
	n := copy(right[1:], right[:4])
	fmt.Println(n, right)

	left := []int{1, 2, 3, 4, 5}
	n = copy(left, left[2:])
	fmt.Println(n, left)
	left = left[:n]
	fmt.Println(left)
}
```

输出：

```text
4 [1 1 2 3 4]
3 [3 4 5 4 5]
[3 4 5]
```

规范保证 copy 的正确结果不受源和目标内存重叠影响。向右移动时，不会把第一个 `1` 一路错误地覆盖成全 `1`；向左移动后，尾部 `4、5` 仍留在数组中，因为 copy 没有自动清理它们。`left = left[:n]` 才让这个切片当前只保留三个元素。

因此，删除或过滤逻辑除了移动元素，还要明确新的长度；如果被移除部分包含指针、切片或其他引用，还要考虑清除不再需要的尾部引用。不能把“当前切片打印不到旧元素”误认为“旧引用一定已经消失”。正式项目可按契约选择标准库的切片操作函数，相关使用场景在后文说明。

**示例 S-13：slices.Clone 是浅复制，二维数据要看复制了哪一层。** 根据官方 `slices.Clone` 文档的浅复制约定编写。

```go
// 运行示例：S-13
package main

import (
	"fmt"
	"slices"
)

func main() {
	src := [][]int{{1, 2}, {3, 4}}
	outer := slices.Clone(src)
	outer[0][0] = 99
	outer[1] = []int{7, 8}
	fmt.Println("src:", src)
	fmt.Println("outer:", outer)

	separate := make([][]int, len(src))
	for i := range src {
		separate[i] = slices.Clone(src[i])
	}
	separate[0][1] = 200
	fmt.Println("src again:", src)
	fmt.Println("separate:", separate)
}
```

输出：

```text
src: [[99 2] [3 4]]
outer: [[99 2] [7 8]]
src again: [[99 2] [3 4]]
separate: [[99 200] [3 4]]
```

“浅复制”表示把每个元素按赋值规则复制一遍。`src` 的元素类型是 `[]int`，因此复制外层元素时，得到的是各行切片值的副本；副本中的行仍引用原来的整数数组。`outer[0][0] = 99` 修改共享的第一行；`outer[1] = []int{7, 8}` 则只替换外层副本中的第二个行切片，原来的第二行仍为 `[3 4]`。

`separate` 先创建独立的外层切片，再为每一行复制整数元素，因此这个二维整数例子实现了行数据隔离。它不是适用于所有对象图的通用深复制算法：如果元素还包含 map、指针或其他共享对象，就需要继续明确哪些层应该复制、哪些身份应该保留。

对于普通 `[]int`，`slices.Clone(src)` 能直接得到元素副本；它还会保留输入的 nil 状态，但不承诺结果容量恰好等于长度。所以不要通过检查某个固定容量值来判断是否克隆成功。

复制时还要检查接口状态是否需要保留。`make([]T, len(src))` 即使输入为 nil，也会构造一个非 nil 空切片；而 `slices.Clone` 保留 nil 与非 nil 的区别。另一种常见写法 `append([]T(nil), src...)` 在源没有元素时得到 nil，也不完全等价于 Clone 的状态约定。单纯的数值计算常常只关心元素，但序列化或公共接口可能把这两种状态赋予不同含义，选用复制方式时应一起核对。

| 操作 | 是否复制切片元素 | 是否保证内部引用指向独立对象 |
| --- | --- | --- |
| `b := a` 或 `b := a[:]` | 否 | 否 |
| `make` 后 `copy` | 是，按赋值规则复制 | 否 |
| `slices.Clone(a)` | 是，浅复制 | 否 |
| 按业务递归复制需要隔离的各层 | 取决于实现 | 仅对明确处理的层成立 |

官方依据：[Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)、[slices.Clone](https://pkg.go.dev/slices#Clone)、[The mechanics of append：copy 与移动元素](https://go.dev/blog/slices)。

<a id="section-3-5"></a>

### 3.5 切片的切片

对已有切片再次执行切片表达式，通常称为“重新切片”或“子切片”。关键不是数冒号，而是先把当前切片的起点、长度和容量写清，再计算新的范围。

<a id="heading-039"></a>

#### 两下标形式：长度缩小，不一定限制后面的容量

对切片 `s` 执行 `s[low:high]` 时，合法边界满足 `0 <= low <= high <= cap(s)`；省略的 high 仍默认取 `len(s)`。结果长度是 `high-low`，容量是 `cap(s)-low`。对数组切片时，数组长度同时提供初始容量上界。

**示例 S-14：子切片还能向后扩展到哪里？**

```go
// 运行示例：S-14
package main

import "fmt"

func main() {
	base := []int{0, 10, 20, 30, 40, 50}
	first := base[1:4]
	second := first[1:3]
	extended := second[:cap(second)]

	fmt.Println("first:", first, len(first), cap(first))
	fmt.Println("second:", second, len(second), cap(second))
	fmt.Println("extended:", extended, len(extended), cap(extended))
}
```

输出：

```text
first: [10 20 30] 3 5
second: [20 30] 2 4
extended: [20 30 40 50] 4 4
```

按层计算即可：`base` 长度和容量都是 6；`first` 从索引 1 开始，所以长度 `4-1=3`、容量 `6-1=5`；`second` 再跳过 first 的第一个元素，所以长度 `3-1=2`、容量 `5-1=4`。它从原数组的数值 `20` 开始，到原数组末尾还有四个位置。

`first` 当前只展示到 `30`，并未把自己后面的容量封住，所以 `second` 可以通过重新切片重新看到 `40、50`。不过它不能向起点之前扩展；切片索引不允许负数，也不能通过 `second[-1:]` 找回 `10`。如果仍然需要原范围，应保留对应的原始切片变量。

<a id="heading-040"></a>

#### 三下标形式：同时指定长度与容量边界

完整切片表达式写成 `s[low:high:max]`，结果长度仍为 `high-low`，容量则改为 `max-low`，要求 `0 <= low <= high <= max <= cap(s)`。只有 low 可以省略，high 与 max 必须明确给出。它适用于数组、数组指针和切片，不适用于字符串。

**示例 S-15：限制容量可隔开未来追加，但不会复制已有元素。**

```go
// 运行示例：S-15
package main

import "fmt"

func main() {
	base := []int{10, 20, 30, 40}
	limited := base[1:3:3]
	limited[0] = 200

	extended := append(limited, 99)
	extended[0] = 7

	fmt.Println("base:", base)
	fmt.Println("limited:", limited, len(limited), cap(limited))
	fmt.Println("extended:", extended, len(extended))
}
```

输出：

```text
base: [10 200 30 40]
limited: [200 30] 2 2
extended: [7 30 99] 3
```

`base[1:3:3]` 的起点是 base 的索引 1，长度 `3-1=2`，容量同样为 2。它最初与 base 共享已有元素，因此第一次写 `limited[0] = 200` 会改变 `base[1]`。

之后追加一个元素，需要长度 3，超过 limited 允许的容量 2，append 必须为结果使用新的底层数组。原来的 `base[3]` 不会被写成 99；`extended[0] = 7` 也只修改新数组，limited 和 base 仍看到 200。示例不输出新容量，因为这里需要说明的是“超过上限后使用新数组”，具体多预留多少位置不属于这个语言规则的保证。

三下标写法常用于限制交给其他代码的切片可以通过追加覆盖的范围。例如把当前可见部分收紧为 `s[:len(s):len(s)]`，至少追加一个元素就不能复用原切片的这段容量。但它仍允许修改已有元素，其他别名也仍能修改同一数组，所以不能将其当成只读机制、深复制机制或并发同步机制。

| 需要实现的目标 | 合适的操作 | 仍要注意的边界 |
| --- | --- | --- |
| 仅观察连续的一段元素 | `s[low:high]` | 共享元素，也可能保留后续容量 |
| 让这个视图的追加无法写入更后面的区间 | `s[low:high:high]` | 已有元素依然共享 |
| 修改结果时不影响原来的普通元素 | 复制到独立切片 | 元素内的引用还需要分别判断 |
| 暂时把缓冲区长度归零以便复用 | `s = s[:0]` | 内容和底层数组并未因此被清除 |

本节推导直接依据 [Slice expressions](https://go.dev/ref/spec#Slice_expressions) 和 [Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)。遇到复杂表达式时，先写出起点对应哪个原数组索引，再分别计算长度和容量，最后判断元素是否共享，通常就能解释输出。

<a id="section-3-6"></a>

### 3.6 切片扩容

扩容发生在现有容量不足以容纳追加结果时。需要区分两件事：`append` 返回一个表示追加结果的切片值；只有在容量不足时，它才必须为结果分配新的底层数组。容量足够时，追加的数据会写入原来的底层数组。

因此，判断追加后谁能看到修改，不能只看变量名称，也不能只看有没有调用 `append`。应先列出追加前的长度与容量，再判断旧切片和新切片是否仍引用同一个数组。下面两例只依赖规范保证，不依赖某个 Go 版本采用多少倍的增长策略。[官方依据：Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)。

<a id="section-3-6-1"></a>

#### 3.6.1 容量足够：底层数组复用，长度分别保存

**示例 T-01：追加成功，不会自动改变另一个切片变量的长度。**

```go
// 运行示例：T-01
package main

import "fmt"

func main() {
	original := make([]int, 2, 4)
	original[0], original[1] = 10, 20
	grown := append(original, 30)
	grown[0] = 100

	fmt.Println("original:", original, "len:", len(original))
	fmt.Println("grown:", grown, "len:", len(grown))
	fmt.Println("resliced:", original[:3])
}
```

输出：

```text
original: [100 20] len: 2
grown: [100 20 30] len: 3
resliced: [100 20 30]
```

原切片的长度为 2、容量为 4，追加一个元素后需要长度 3，仍在容量范围内。`grown` 与 `original` 因此共享数组；`grown[0] = 100` 能被 `original[0]` 观察到。但是两个切片值各自保存长度，所以 `len(original)` 仍为 2。

`original[:3]` 可以取得长度为 3 的新视图，因为上界没有超过其容量；这不表示 `original[2]` 原本就能直接访问。索引受当前长度约束，重新切片的上界按切片表达式规则判断。追加不改变原切片变量的长度，正是通常需要写 `s = append(s, value)` 的原因。

<a id="section-3-6-2"></a>

#### 3.6.2 容量不足：新旧切片可以分开观察

**示例 T-02：新数组保存追加结果，旧指针仍指向旧元素。**

```go
// 运行示例：T-02
package main

import "fmt"

func main() {
	old := []int{10, 20} // len 和 cap 都是 2
	first := &old[0]
	grown := append(old, 30)
	grown[0] = 99

	fmt.Println("old:", old)
	fmt.Println("grown:", grown)
	fmt.Println("old pointer:", *first)

	*first = 77
	fmt.Println("after pointer write:", old, grown)
	fmt.Println("enough capacity:", cap(grown) >= len(grown))
}
```

输出：

```text
old: [10 20]
grown: [99 20 30]
old pointer: 10
after pointer write: [77 20] [99 20 30]
enough capacity: true
```

追加后需要三个元素，原容量只有两个，必须得到新的底层数组。原切片可见的两个整数先复制到新数组，再形成追加结果。此后修改 `grown[0]` 不会修改 `old[0]`。

`first` 不会随着切片扩容自动“搬到”新数组，它仍指向旧数组中的第一个整数。只要旧数组还通过切片或指针被使用，Go 就必须保证相应存储仍然有效；这里不会产生因为 append 而悬空的普通 Go 指针。它可能在业务上不再指向开发者想跟踪的“当前列表第一个元素”，这是对象身份的问题。[官方依据：切片共享与增长](https://go.dev/blog/slices-intro)、[Go FAQ：变量的存储与生命周期](https://go.dev/doc/faq#stack_or_heap)。

“复制元素”遵循赋值语义。如果元素是 `int`，复制的是整数；如果元素是 `*Record`、切片或包含引用的结构体，复制元素后仍可能共享元素指向的数据。扩容本身不提供递归深拷贝，也不会为并发访问提供同步。

<a id="section-3-6-3"></a>

#### 3.6.3 应该依赖哪些保证

| 可以用来推导程序行为 | 应留给实现或实际测量的问题 |
| --- | --- |
| 容量足够时 append 复用原底层数组 | 新数组具体预留多少额外容量 |
| 容量不足时为追加结果分配足够大的数组 | 某次扩容最终分配了多少字节 |
| 返回切片具有追加后的内容和长度 | 不同元素类型、平台和 Go 版本的具体容量序列 |
| 旧切片变量的长度不会自动更新 | 某段代码最终在栈还是堆上分配 |

知道预计元素数量时，`make([]T, 0, n)` 可以先预留空间，使接下来的至多 `n` 个追加元素能够放入该数组。它不会预先创建 `n` 个可索引元素。应根据数据规模选择容量，而不是在所有函数中盲目预留很大的数组；空闲容量同样需要相应存储。更细的运行时增长算法在 3.11 中单独分析。

扩容还影响单次操作的工作量：追加一个整数时，若仍有空位，只需形成新切片值并写入相应元素；若没有空位，除了写入这个新元素，还需要把现有切片元素复制到新数组。因此不能把每一次 append 都理解成相同的固定代价。整体追加的表现要结合具体增长策略、元素大小和调用方式分析。

旧数组也不一定在扩容后立刻失去用途。T-02 中，`old` 和 `first` 仍然访问它，所以新旧数组可以同时被保留。预留容量、减少无意义的旧别名与避免长期保存过大的数据视图，分别解决不同的问题，不能用一个“扩容后自动释放”的说法代替这些判断。这里分析的是复制与引用关系，不从一次运行结果推断具体 GC 时间。

<a id="section-3-7"></a>

### 3.7 切片作为函数参数和返回值

<a id="section-3-7-1"></a>

#### 3.7.1 切片参数按值传递

函数收到切片时，得到的是切片值的副本。可以把这个副本理解为一份描述“从哪里开始、当前多长、最多可重新切到多长”的信息；底层数组不会因为传参就整体复制。

修改 `s[i]` 会访问共享数组的元素；给局部参数 `s` 重新赋值、缩短它或让它保存 append 的返回结果，只会改变这个参数变量。需要让调用方采用新的长度或新数组时，通常将新切片作为返回值交出去。[官方依据：Calls](https://go.dev/ref/spec#Calls)、[Slice types](https://go.dev/ref/spec#Slice_types)。

**示例 T-03：修改元素、局部追加、接收返回值。**

```go
// 运行示例：T-03
package main

import "fmt"

func editLocally(values []int) {
	values[0] = 9
	values = append(values, 7)
	fmt.Println("inside:", values)
}

func add(values []int, value int) []int {
	return append(values, value)
}

func main() {
	values := make([]int, 2, 4)
	values[0], values[1] = 1, 2
	editLocally(values)
	fmt.Println("outside:", values)
	fmt.Println("underlying prefix:", values[:3])

	values = add(values, 8)
	fmt.Println("after returned slice:", values)
}
```

输出：

```text
inside: [9 2 7]
outside: [9 2]
underlying prefix: [9 2 7]
after returned slice: [9 2 8]
```

第一次调用把共享的第一个元素改为 `9`，并在数组的第三个位置写入 `7`。但是外层切片的长度仍是 2。第二次调用从这个长度为 2 的切片追加 `8`，追加位置仍是索引 2，所以原来的 `7` 被覆盖。调用方这次接收了返回值，长度才更新为 3。

这个例子也解释了为什么不能根据“函数内 append 后看起来有第三个元素”判断调用方已经得到它。函数接口应说明究竟会修改元素、返回新视图，还是独立创建结果。只有确实要直接重写调用方切片变量时才需要 `*[]T`；大多数追加、筛选和转换函数返回 `[]T` 就足够清楚。

<a id="section-3-7-2"></a>

#### 3.7.2 返回共享视图，还是返回独立结果

返回 `s[low:high]` 通常方便且不复制元素，但调用方会继续与原数据共享数组。返回新建切片中的副本，则可以让外层数组的后续修改不影响结果。这是接口语义的选择，不能只比较哪种写法更短。

**示例 T-04：两个同样内容的返回值，后续行为不同。**

```go
// 运行示例：T-04
package main

import "fmt"

func middleView(values []int) []int {
	return values[1:3]
}

func middleCopy(values []int) []int {
	result := make([]int, 2)
	copy(result, values[1:3])
	return result
}

func main() {
	data := []int{10, 20, 30, 40}
	view := middleView(data)
	owned := middleCopy(data)
	data[1] = 99

	fmt.Println("view:", view)
	fmt.Println("copy:", owned)
	fmt.Println("copy length and capacity:", len(owned), cap(owned))
}
```

输出：

```text
view: [99 30]
copy: [20 30]
copy length and capacity: 2 2
```

两个函数都约定输入至少有三个元素；实际公共接口应检查边界或明确记录这个前提。`middleCopy` 使用 `make` 和 `copy` 建立两个整数的独立存储，返回的切片不依赖原数组。这种方式也适用于“从很大的输入中只保留一小段”的场景。

官方博客指出，长期保存一个很小的子切片，仍可能使整个较大的底层数组保持可达。复制所需片段可切断这一数组共享关系，但实际回收时机由垃圾回收器决定，不能从一次输出推断内存已立即返还给操作系统。对包含指针的元素，浅复制还可能继续保留被指向对象。[官方示例：Go Slices 的 A possible gotcha](https://go.dev/blog/slices-intro)、[slices.Clone 的浅拷贝约定](https://pkg.go.dev/slices#Clone)。

给切片函数写注释时，可以把行为拆成下面四项，避免一句“返回处理后的切片”留下歧义：

| 接口问题 | 清楚的说明示例 |
| --- | --- |
| 是否写入输入元素 | 本函数会原地排序；或者只读取输入 |
| 结果是否共享数组 | 返回输入的一个视图；或者复制所需元素到新数组 |
| 长度变化如何交给调用方 | 调用方必须保存返回切片，例如 `s = remove(s)` |
| nil、空输入和非法范围怎样处理 | nil 作为空序列接受；非法范围返回 error 或按约定 panic |

函数参数的静态类型 `[]T` 不会自动表达这些约定。相同的签名既能实现只读查询，也能实现原地修改；是否需要复制，应由调用者与函数之间的共享约定决定。若不同 goroutine 会同时访问重叠元素，且至少一方写入，还要额外建立同步关系；复制切片值本身没有消除共享，也不能代替互斥或消息传递。[官方依据：Go 内存模型](https://go.dev/ref/mem)。

<a id="section-3-8"></a>

### 3.8 切片常见的使用场景

切片适合表示数量随运行过程变化、需要按索引或顺序访问的数据。使用前先确定三个约定：是否保留原顺序、是否允许修改输入，以及结果是否与输入共享数据。下面从数据组织方式开始，再进入筛选、排序和删除。

| 场景 | 切片承担的角色 | 要额外明确的问题 |
| --- | --- | --- |
| 收集查询或计算结果 | 按顺序追加元素 | 预计数量、是否预留容量 |
| 栈 | 从尾部压入、从尾部取出 | 空栈检查，废弃位置是否保留引用 |
| 小型队列 | 尾部追加、从头部取出 | 原数组保留时间，是否需要更专门的结构 |
| 批处理或分页窗口 | 对同一数据划分子切片 | 窗口是否共享、追加能否影响相邻窗口 |
| 数据清洗与统计 | 筛选、转换、排序、去重 | 是否改变顺序、是否丢弃重复记录 |

**示例 T-05：用切片表达栈与队列。** 根据 append、切片表达式和零值赋值规则编写；本例预先保证容器非空。

```go
// 运行示例：T-05
package main

import "fmt"

type Job struct {
	ID int
}

func main() {
	stack := []*Job{{ID: 1}, {ID: 2}}
	lastIndex := len(stack) - 1
	last := stack[lastIndex]
	stack[lastIndex] = nil
	stack = stack[:lastIndex]
	fmt.Println("pop:", last.ID, "remaining:", len(stack))

	queue := []*Job{{ID: 10}, {ID: 20}, {ID: 30}}
	first := queue[0]
	queue[0] = nil
	queue = queue[1:]
	fmt.Println("dequeue:", first.ID, "front:", queue[0].ID, "remaining:", len(queue))
}
```

输出：

```text
pop: 2 remaining: 1
dequeue: 10 front: 20 remaining: 2
```

先取出元素，再清空原位置，最后调整切片范围。清空对 `int` 元素的逻辑结果通常没有必要，但对这里的指针元素，可以去掉数组中已经废弃的引用。`last` 与 `first` 自己仍持有取出的对象，因而清空位置不表示对象马上被回收。

切片从头部不断前移，也可能长期保留原数组；持续吞吐、容量有明确上限的队列可以考虑环形缓冲等结构。本例用于说明操作与共享关系，不把“用切片写得出来”推导成“适合所有队列负载”。相关内存问题见 [Robust generic functions on slices](https://go.dev/blog/generic-slice-functions)。

**示例 T-06：把数据划分成大小受限的批次。**

```go
// 运行示例：T-06
package main

import (
	"errors"
	"fmt"
)

func batches(values []int, size int) ([][]int, error) {
	if size <= 0 {
		return nil, errors.New("batch size must be positive")
	}
	var result [][]int
	for start := 0; start < len(values); {
		count := min(size, len(values)-start)
		end := start + count
		result = append(result, values[start:end:end])
		start = end
	}
	return result, nil
}

func main() {
	data := []int{1, 2, 3, 4, 5}
	parts, err := batches(data, 2)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println("batches:", parts)
	parts[1][0] = 99
	expanded := append(parts[0], 7)
	fmt.Println("data:", data)
	fmt.Println("expanded first batch:", expanded)
}
```

输出：

```text
batches: [[1 2] [3 4] [5]]
data: [1 2 99 4 5]
expanded first batch: [1 2 7]
```

外层 `[][]int` 保存多个切片值，各批次仍是原数组的视图。第二批第一个元素对应原数据索引 2，写入会改变原数据。三下标形式把每个批次的容量限制到自己的长度，因此对第一批继续追加必须另找数组，不能直接覆盖紧随其后的批次。

这项容量限制没有隔离已有元素；如果下游连已有元素都不应该修改，就应复制批次，或者用接口约定和只读处理流程控制访问。例子使用的内置 `min` 从 Go 1.21 起可用；批次计算先取剩余数量再相加，也避免直接使用不受限制的 `start + size`。[官方依据：Slice expressions](https://go.dev/ref/spec#Slice_expressions)、[Min and max](https://go.dev/ref/spec#Min_and_max)。

<a id="section-3-8-1"></a>

#### 3.8.1 使用切片进行数据处理

**一、筛选：决定保留哪些元素，并保留原有次序。**

筛选函数把规则作为回调传入，遍历框架只负责检查每个元素、追加通过检查的值。下面改编自官方切片博客的 `Filter` 示例，补充了完整入口并预留最多与输入等长的容量。

```go
// 运行示例：T-07
package main

import "fmt"

func filter(values []int, keep func(int) bool) []int {
	result := make([]int, 0, len(values))
	for _, value := range values {
		if keep(value) {
			result = append(result, value)
		}
	}
	return result
}

func main() {
	data := []int{4, -1, 8, 3, 0}
	selected := filter(data, func(value int) bool {
		return value >= 0 && value%2 == 0
	})
	fmt.Println("selected:", selected)
	selected[0] = 100
	fmt.Println("input:", data)
}
```

输出：

```text
selected: [4 8 0]
input: [4 -1 8 3 0]
```

规则接受非负偶数，因此保留 `4、8、0`，次序与原输入相同。结果切片独立存储这些整数，所以修改结果不会改变输入。这里约定 `keep` 非 nil，并且只按当前示例读取整数；如果回调自行修改外部状态，筛选框架不会替它消除副作用。

筛选结果的最大长度是输入长度，预留相同容量可以减少追加时的重新分配；若实际通过率很低而输入极大，预留策略也可能浪费空间，可以从 nil 切片开始或依据可用估计决定容量。这个取舍不会改变筛选规则本身。[官方来源：Go Slices 的 Filter 示例](https://go.dev/blog/slices-intro)。

**二、排序与去重：相邻重复和全局重复要分清。**

标准库 `slices` 从 Go 1.21 起提供常用切片算法。`Sort` 会原地排序，`Compact` 会将相邻的相等元素压缩成一个，并返回缩短后的切片。如果希望对所有相同值去重，可先排序再压缩；这样也会改变原有次序。[官方依据：slices.Sort](https://pkg.go.dev/slices#Sort)、[slices.Compact](https://pkg.go.dev/slices#Compact)。

这里的 `slices` 是标准库包，不需要额外安装第三方模块，但仍需使用支持它的工具链。较早工具链没有这个包；仅修改 `go.mod` 的版本文字，并不能让旧编译器获得新版标准库。其加入标准库的版本可核对 [Go 1.21 发布说明](https://go.dev/doc/go1.21)。

**示例 T-08：在副本中排序去重，并进行二分查找。** 改编自官方泛型切片博客中 Clone、Sort、Compact 的组合示例。

```go
// 运行示例：T-08
package main

import (
	"fmt"
	"slices"
)

func main() {
	input := []int{3, 1, 3, 2, 2}
	adjacent := slices.Compact(slices.Clone(input))
	ordered := slices.Clone(input)
	slices.Sort(ordered)
	ordered = slices.Compact(ordered)

	fmt.Println("adjacent only:", adjacent)
	fmt.Println("sorted unique:", ordered)
	fmt.Println("input:", input)
	index, found := slices.BinarySearch(ordered, 2)
	fmt.Println("search 2:", index, found)
}
```

输出：

```text
adjacent only: [3 1 3 2]
sorted unique: [1 2 3]
input: [3 1 3 2 2]
search 2: 1 true
```

第一种处理只消除了末尾相邻的两个 `2`，分开的两个 `3` 都保留。第二种处理先排序，让相同值相邻，再得到有序的唯一值集合。`Clone` 使两条处理路径不改动输入切片的整数元素；它按赋值复制元素，对切片或指针元素仍是浅复制。

`BinarySearch` 要求输入按它采用的顺序排好。这里的结果 `[1 2 3]` 满足条件，值 `2` 的索引是 1；不能因为函数名包含“查找”，就对任意未排序切片直接使用。若使用自定义比较器排序，也需保证查找采用一致的顺序。[官方依据：slices.BinarySearch](https://pkg.go.dev/slices#BinarySearch)、[slices.Clone](https://pkg.go.dev/slices#Clone)。

当元素变成含多个字段的记录时，通常需要 `slices.SortFunc` 明确比较字段。比较函数返回负数、零、正数，分别表示应排在前面、比较意义上相等、应排在后面。整数比较可以使用 `cmp.Compare(a.Score, b.Score)`，避免用 `a.Score - b.Score` 时可能发生的算术溢出。若分数相同仍希望保持这些记录在输入中的先后关系，应使用 `slices.SortStableFunc`；“稳定”在这里专指比较相等的元素保持相对顺序，不表示函数不会修改输入。

排序规则与去重规则也要分别设计。两位学生分数相同，可以在按分数排序时视作并列，却不能据此删除其中一位。给 `CompactFunc` 编写相等判断时，必须使用业务真正认可的重复条件，并确保要压缩的记录在当前顺序中相邻。[官方依据：slices.SortFunc](https://pkg.go.dev/slices#SortFunc)、[slices.SortStableFunc](https://pkg.go.dev/slices#SortStableFunc)、[cmp.Compare](https://pkg.go.dev/cmp#Compare)。

**三、保留第一次出现的顺序：用辅助集合判断是否见过。**

如果业务希望输入 `3、1、3、2` 变成 `3、1、2`，排序后压缩不符合要求。可以依次扫描输入，用 map 记录出现过的整数，只把首次出现的值追加到结果。顺序来自扫描切片，而不是遍历 map。

```go
// 运行示例：T-09
package main

import "fmt"

func uniqueInOrder(values []int) []int {
	seen := make(map[int]struct{}, len(values))
	result := make([]int, 0, len(values))
	for _, value := range values {
		if _, exists := seen[value]; exists {
			continue
		}
		seen[value] = struct{}{}
		result = append(result, value)
	}
	return result
}

func main() {
	input := []int{3, 1, 3, 2, 2}
	fmt.Println(uniqueInOrder(input))
	fmt.Println(input)
}
```

输出：

```text
[3 1 2]
[3 1 3 2 2]
```

`map[int]struct{}` 在这里只表示集合：关心键是否存在，不需要额外业务值；`struct{}{}` 是空结构体值。这个方法消耗额外的集合与结果存储，以换取首次出现顺序的保留。若元素不能作为 map 键，例如元素本身是切片，就需要设计可比较的身份键或明确的相等判定，不能直接把类型替换进去。这个数据处理程序为本笔记自行组织，使用的集合判断规则见 [Map types](https://go.dev/ref/spec#Map_types)、[Index expressions](https://go.dev/ref/spec#Index_expressions)。

**四、删除：接收新长度，并处理废弃尾部。**

`slices.Delete(s, i, j)` 删除半开区间 `[i, j)`，把后续元素移到前面，再返回缩短后的切片。它会修改原数组，不能把删除前的别名当成仍然有效的旧数据快照。

```go
// 运行示例：T-10
package main

import (
	"fmt"
	"slices"
)

func main() {
	names := []string{"A", "B", "C", "D"}
	oldView := names
	names = slices.Delete(names, 1, 3)
	fmt.Printf("result: %q len=%d\n", names, len(names))
	fmt.Printf("old view: %q len=%d\n", oldView, len(oldView))
}
```

以下输出依据 Go 1.22 及以上标准库的尾部清理行为。

输出：

```text
result: ["A" "D"] len=2
old view: ["A" "D" "" ""] len=4
```

`B、C` 被删除，`D` 前移到索引 1。当前标准库还会把新长度与旧长度之间的废弃元素置为零值，这里就是两个空字符串。旧切片值的长度仍为 4，因此本例特意通过它观察底层数组变化；实际处理流程应继续使用返回的新切片，不能将旧视图当成删除前的内容。

尾部清理从 Go 1.22 起成为这些缩短切片函数的行为，包括 `Delete`、`DeleteFunc`、`Compact`、`CompactFunc` 和 `Replace`。若废弃元素包含指针，清理能够移除对不再需要的对象的引用；它不等于缩小底层数组的分配。自行实现原地筛选时，也要考虑是否需要清空废弃区间。[官方依据：Go 1.22 发布说明](https://go.dev/doc/go1.22)、[slices.Delete](https://pkg.go.dev/slices#Delete)、[Robust generic functions on slices](https://go.dev/blog/generic-slice-functions)。

### 3.9 切片和数组的简单比较

数组适合把固定数量直接纳入类型，例如三个坐标或一个固定长度摘要。切片适合让长度成为运行时数据，例如本次查询返回多少行、当前积累了多少任务。选择时应考虑类型约束、共享关系和操作方式，而不是简单记成“数组旧，切片新”。

| 比较项 | 数组 `[N]T` | 切片 `[]T` |
| --- | --- | --- |
| 长度是否属于类型 | 是，`[3]int` 与 `[4]int` 不同 | 否，不同长度的 `[]int` 类型相同 |
| 变量直接表示什么 | 包含 N 个元素的数组值 | 某个底层数组区间的切片值 |
| 赋值与普通参数传递 | 复制整个数组值 | 复制切片值，通常继续共享数组 |
| 能否改变当前变量的长度 | 数组长度固定 | 可接收重新切片或 append 返回的新值 |
| 零值 | 每个数组元素都是元素类型的零值 | nil 切片，长度与容量都为 0 |
| `==` 的使用 | 元素类型可比较时，数组才可比较 | 只可与 nil 比较；内容比较需另用规则 |
| 常见函数参数 | `[N]T` 表达固定长度，或用 `*[N]T` 共享数组 | `[]T` 接受不同长度，并明确是否修改元素 |
| 引用字段的复制 | 元素内的指针等仍可共享目标 | 底层元素共享，进一步复制也要看元素类型 |

**示例 T-11：数组赋值与切片赋值并排观察。**

```go
// 运行示例：T-11
package main

import (
	"fmt"
	"slices"
)

func main() {
	a := [3]int{1, 2, 3}
	b := a
	b[0] = 9
	fmt.Println("arrays:", a, b, a == b)

	s := a[:]
	t := s
	t[1] = 8
	fmt.Println("array after slice write:", a)
	fmt.Println("slices:", s, t)
	fmt.Println("equal contents:", slices.Equal(s, t))
}
```

输出：

```text
arrays: [1 2 3] [9 2 3] false
array after slice write: [1 8 3]
slices: [1 8 3] [1 8 3]
equal contents: true
```

数组 `b` 是整数元素的独立副本；切片 `s` 和 `t` 则都引用数组 `a` 的元素，所以通过 `t` 写入会改变 `a`。`slices.Equal` 逐元素比较内容，不是在判断两个切片变量是否具有同一个底层数组。即使两个结果来自不同数组，只要可比较元素逐项相等，它也可返回 true。[官方依据：Array types](https://go.dev/ref/spec#Array_types)、[Slice types](https://go.dev/ref/spec#Slice_types)、[Comparison operators](https://go.dev/ref/spec#Comparison_operators)、[slices.Equal](https://pkg.go.dev/slices#Equal)。

例如，函数参数写成 `[4]byte`，长度 4 就成为编译期检查的一部分；写成 `[]byte` 则允许不同长度，若业务只接受四字节标识，函数内部还应检查长度。反过来，一个批次的记录数量经常变化，将其写成固定数组会让“当前用了多少位置”变成另一个必须维护的状态。类型应表达稳定的约束，切片长度应表达本次数据的实际范围。

两者也可以配合使用：一个固定数组作为存储，临时用它的一段切片交给需要 `[]T` 的函数。但此时函数可能通过切片修改数组，所以“原来是数组”并不等于“交出去后不会共享”。是否复制、是否共享、是否接受长度变化，始终要按具体表达式和函数契约判断。

### 3.10 切片小案例

<a id="section-3-10-1"></a>

#### 3.10.1 任务：生成一份成绩分布与合格分数清单

输入是一批整数成绩与合格线。我们希望先检查数据是否在 0 到 100 范围内，再统计各分数段人数，筛出达到合格线的成绩，并生成升序排列的唯一分数清单。重复成绩代表不同记录，因此“合格人数”需要保留重复记录，“唯一分数清单”才进行去重。

设计两个容器：`[]int` 保存长度不定的唯一分数清单；`[3]int` 保存三个固定区间的人数，依次对应 `0–59`、`60–79`、`80–100`。合格线只影响合格人数与清单，不改变这三个统计区间。函数不修改输入，发现无效数据就返回错误和零值报告，不对外提供部分统计。

下面的业务流程为本笔记编写，使用的排序、压缩和切片操作均依据前述官方接口；它也把数组与切片放在同一个有实际含义的结构体中。

```go
// 运行示例：T-12
package main

import (
	"errors"
	"fmt"
	"slices"
)

type Report struct {
	Total         int
	Passed        int
	UniquePassing []int
	Buckets       [3]int
}

func summarize(scores []int, threshold int) (Report, error) {
	if threshold < 0 || threshold > 100 {
		return Report{}, errors.New("threshold must be in [0,100]")
	}
	result := Report{
		Total:         len(scores),
		UniquePassing: make([]int, 0, len(scores)),
	}
	for i, score := range scores {
		if score < 0 || score > 100 {
			return Report{}, fmt.Errorf("score[%d]=%d is outside [0,100]", i, score)
		}
		switch {
		case score < 60:
			result.Buckets[0]++
		case score < 80:
			result.Buckets[1]++
		default:
			result.Buckets[2]++
		}
		if score >= threshold {
			result.Passed++
			result.UniquePassing = append(result.UniquePassing, score)
		}
	}
	slices.Sort(result.UniquePassing)
	result.UniquePassing = slices.Compact(result.UniquePassing)
	return result, nil
}

func main() {
	input := []int{80, 55, 92, 80, 60, 72}
	report, err := summarize(input, 60)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println("total and passed:", report.Total, report.Passed)
	fmt.Println("unique passing:", report.UniquePassing)
	fmt.Println("buckets:", report.Buckets)
	fmt.Println("input:", input)

	empty, err := summarize(nil, 60)
	fmt.Println("empty:", empty.Total, empty.Passed, empty.UniquePassing, err)
	_, err = summarize([]int{80, 101}, 60)
	fmt.Println("invalid score:", err)
	_, err = summarize(input, 120)
	fmt.Println("invalid threshold:", err)
}
```

输出：

```text
total and passed: 6 5
unique passing: [60 72 80 92]
buckets: [1 2 3]
input: [80 55 92 80 60 72]
empty: 0 0 [] <nil>
invalid score: score[1]=101 is outside [0,100]
invalid threshold: threshold must be in [0,100]
```

<a id="section-3-10-2"></a>

#### 3.10.2 逐步读懂结果

1. 合格线为 60，输入六条记录全部通过合法范围检查。`Total` 因而为 6。
2. 成绩 `55` 落入第一个分组，`60、72` 落入第二组，两个 `80` 与 `92` 落入第三组，所以分组结果为 `[1 2 3]`。
3. 达到合格线的五条记录依次被追加为 `[80 92 80 60 72]`，`Passed` 为 5。
4. 排序得到 `[60 72 80 80 92]`，相邻压缩得到 `[60 72 80 92]`。这份清单有四个值，不应据此把五位合格记录改算成四条。
5. 原始输入从未用于原地排序，保持原有顺序。空输入仍得到有效的空报告；无效成绩或合格线则明确返回错误。

这个流程的关键在于先定义结果含义，再选择算法。若需求变成“保留第一次出现的顺序”，应使用 T-09 的处理方式；若需要保留每条记录的身份，则应使用带姓名或编号的结构体，并避免仅凭分数删除不同记录。`Compact` 判断的是元素相等，无法替业务决定“哪些记录算重复”。

对函数契约也应保持一致：本例任何输入错误都返回零值报告，调用方应先检查错误；如果设计为允许部分结果，就需要在注释与调用方逻辑中明确说明。将输入检查、数组统计和切片处理拆成有含义的阶段，比把所有操作压缩成一行更便于核对。

本节主要接口来源：[slices.Sort](https://pkg.go.dev/slices#Sort)、[slices.Compact](https://pkg.go.dev/slices#Compact)、[errors.New](https://pkg.go.dev/errors#New)、[fmt.Errorf](https://pkg.go.dev/fmt#Errorf)。

### 3.11 切片的底层操作

前面的示例已经能够解决多数日常任务。本节再沿着“切片值怎样描述数据、复制时复制哪一层、容量不足时怎样安排存储”的顺序，把容易混淆的底层关系串起来。理解这些关系，是为了准确判断程序行为，不要求在业务代码里直接操作内存地址。

<a id="section-3-11-1"></a>

#### 3.11.1 创建切片

**先分清切片值与它引用的元素存储。** 语言规范把切片定义为底层数组中一段连续元素的描述。理解一个切片，至少要知道三个信息：它从底层数组的哪个元素开始、目前有多少个可访问元素，以及最多允许把长度扩展到多少。多个切片可以从不同起点观察同一个数组，也可以拥有不同的容量限制。[官方依据：Slice types](https://go.dev/ref/spec#Slice_types)、[Full slice expressions](https://go.dev/ref/spec#Slice_expressions)。

在本次使用的 Go 1.27.3 运行时源码中，这三个信息对应下面的内部结构。这里只展示结构，不是供应用程序直接构造切片的接口：

```go
// 结构示意；来自 Go 运行时 slice.go，不能单独运行。
type slice struct {
    array unsafe.Pointer
    len   int
    cap   int
}
```

其中 `array` 指向该切片起点对应的元素位置，不一定指向原始数组的第一个元素。`len` 和 `cap` 保存在每一个切片值中，因此复制切片值后，两个变量可以保持共享元素，但分别改变自己的长度。内部字段和物理表示属于具体实现；应用代码应使用索引、切片表达式、`len`、`cap`、`append` 等语言操作。[源码依据：runtime/slice.go](https://go.dev/src/runtime/slice.go)。

假设有数组 `a := [6]int{10, 20, 30, 40, 50, 60}`，再分别创建几个切片，它们的关系可以直接列成表：

| 表达式 | 起点相对 `a` 的索引 | `len` | `cap` | 当前可见内容 |
| --- | ---: | ---: | ---: | --- |
| `a[:]` | 0 | 6 | 6 | `[10 20 30 40 50 60]` |
| `a[1:4]` | 1 | 3 | 5 | `[20 30 40]` |
| `a[1:4:4]` | 1 | 3 | 3 | `[20 30 40]` |
| `a[3:3]` | 3 | 0 | 3 | `[]` |

第三行与第二行读取到相同元素，但第三行只允许在这三个位置内重新切片。第四行虽然没有当前可见元素，却仍然可以保留底层数组的引用及后续容量。长度为零不能用来证明“不持有任何存储”。

**创建方式决定初始状态。** `var s []T` 得到 nil 切片；`make([]T, n, c)` 得到长度为 `n`、容量为 `c`、元素初始化为零值的切片；`[]T{...}` 根据元素创建并初始化；`a[i:j]` 或 `s[i:j]` 则在已有存储上建立一个视图。规范对 `make` 用隐藏数组说明其行为，但是否真的进行一次堆分配、是否能够放在栈上或者被优化掉，需要看编译器和具体使用方式，不能仅凭 `make` 这个单词判断。[官方依据：Making slices, maps and channels](https://go.dev/ref/spec#Making_slices_maps_and_channels)、[Go FAQ：堆与栈](https://go.dev/doc/faq#stack_or_heap)。

**`unsafe.Sizeof` 也要分清测量对象。** 对切片值调用它，测到的是切片值本身的大小，不包括底层数组，也不会沿着元素里的指针递归计算所有相关对象。下面使用它比较两个切片值，并计算一个明确的 `int64` 元素区间的字节数；不做地址转换或越界访问。

```go
// 运行示例：R-01
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	small := make([]int64, 2, 4)
	large := make([]int64, 100, 200)
	fmt.Println("same descriptor size:", unsafe.Sizeof(small) == unsafe.Sizeof(large))
	fmt.Println("small length and capacity:", len(small), cap(small))
	fmt.Println("large length and capacity:", len(large), cap(large))
	fmt.Println("int64 element bytes:", unsafe.Sizeof(int64(0)))
	fmt.Println("small capacity element bytes:", uintptr(cap(small))*unsafe.Sizeof(int64(0)))

	p := new([]int)
	fmt.Println("pointer exists, slice is nil:", p != nil, *p == nil)
}
```

输出：

```text
same descriptor size: true
small length and capacity: 2 4
large length and capacity: 100 200
int64 element bytes: 8
small capacity element bytes: 32
pointer exists, slice is nil: true true
```

`32` 只表示四个 `int64` 元素所需的连续元素空间，不能据此声称程序实际只消耗了 32 字节。分配器的取整、其他变量、运行时管理开销，以及是否发生实际分配，都不在这个计算中。更一般地，一个子切片还可能持有比自身 `cap` 所描述范围更大的原始数组，所以 `cap(s) * 元素大小` 也不是通用的“该切片保留内存量”。[官方依据：unsafe.Sizeof](https://pkg.go.dev/unsafe#Sizeof)、[Go Slices：可能的内存持有问题](https://go.dev/blog/slices-intro)。

最后两项说明 `new([]int)` 创建的是一个指向切片零值的指针：指针自身非 nil，所指向的切片仍为 nil。它没有替开发者创建一个长度大于零的 `[]int`。多数需要可追加容器的场合，直接使用 `var s []int` 或 `make([]int, 0, capacity)` 会更清楚。[官方依据：Allocation](https://go.dev/ref/spec#Allocation)。

<a id="section-3-11-2"></a>

#### 3.11.2 nil 和空切片的区别

nil 切片一定满足 `len(s) == 0`、`cap(s) == 0`；反过来，长度和容量都为零的切片也可能非 nil。例如 `[]int{}` 和 `make([]int, 0)` 都是已初始化的非 nil 空切片。`make([]int, 0, 4)` 也是空切片，但它还有四个元素的容量。[官方依据：Slice types](https://go.dev/ref/spec#Slice_types)、[Composite literals](https://go.dev/ref/spec#Composite_literals)。

这一区别影响接口约定，但不妨碍很多普通操作：两者都可以 `range`、作为 `append` 的起点，也都可以传给 `copy`；在没有有效元素时直接访问 `[0]` 都会越界。判断“有没有元素”一般用 `len(s) == 0`；只有当 nil 本身代表一个业务状态时，才额外检查 `s == nil`。

下面同时观察 nil 判断、长度、容量以及 JSON 输出。使用 `[]int`，避免 `encoding/json` 对 `[]byte` 的特殊编码规则混入示例。

```go
// 运行示例：R-02
package main

import (
	"encoding/json"
	"fmt"
	"reflect"
	"slices"
)

func main() {
	var nilSlice []int
	literal := []int{}
	made := make([]int, 0)
	reserved := make([]int, 0, 4)
	cases := []struct {
		name string
		data []int
	}{
		{"nil", nilSlice},
		{"literal", literal},
		{"make", made},
		{"reserved", reserved},
	}
	for _, item := range cases {
		encoded, err := json.Marshal(item.data)
		if err != nil {
			panic(err)
		}
		fmt.Printf("%s: nil=%t len=%d cap=%d json=%s\n",
			item.name, item.data == nil, len(item.data), cap(item.data), encoded)
	}
	fmt.Println("slices.Equal:", slices.Equal(nilSlice, literal))
	fmt.Println("reflect.DeepEqual:", reflect.DeepEqual(nilSlice, literal))
	fmt.Println("Clone nil checks:", slices.Clone(nilSlice) == nil, slices.Clone(literal) == nil)
}
```

输出：

```text
nil: nil=true len=0 cap=0 json=null
literal: nil=false len=0 cap=0 json=[]
make: nil=false len=0 cap=0 json=[]
reserved: nil=false len=0 cap=4 json=[]
slices.Equal: true
reflect.DeepEqual: false
Clone nil checks: true false
```

这里并没有哪一个比较函数“算错了”，它们回答的问题不同：

| 操作 | 对 nil `[]int` 与非 nil 空 `[]int` 的处理 | 适合表达的意思 |
| --- | --- | --- |
| `s == nil` | 能区分两者 | 这个切片值是否为 nil |
| `len(s) == 0` | 两者都为 true | 当前是否没有元素 |
| `slices.Equal(a, b)` | 认为相等 | 可比较元素的序列是否相等 |
| `reflect.DeepEqual(a, b)` | 认为不相等 | 按该函数的深度相等规则比较完整值 |
| `json.Marshal(s)` | 分别得到 `null` 与 `[]` | 默认 JSON 编码结果 |
| `slices.Clone(s)` | 保留输入的 nil 状态 | 复制元素，同时保留这一状态差别 |

来源：[slices.Equal](https://pkg.go.dev/slices#Equal)、[slices.Clone](https://pkg.go.dev/slices#Clone)、[reflect.DeepEqual](https://pkg.go.dev/reflect#DeepEqual)、[encoding/json.Marshal](https://pkg.go.dev/encoding/json#Marshal)。

切片不能用 `a == b` 直接做内容比较，例外是与 nil 比较。不要为了判断两个 `[]int` 的内容而在代码中写 `a == b`，也不要通过打印出来都是 `[]` 就断定 nil 状态相同。

JSON 还有两个常见边界。第一，非 nil 的 `[]byte` 默认编码为 Base64 字符串，非 nil 空字节切片编码为 `""`，nil `[]byte` 仍编码为 `null`；不能把上表中的 `[]int` 示例机械套过去。第二，如果切片放在结构体字段里并带有 `omitempty`，长度为零的字段可能直接被省略；那是字段选项在起作用，不等于切片自身被编码成了 `[]`。API 如果要求固定返回空数组，应明确构造非 nil 空切片，并同时核对字段标签和自定义编码逻辑。[官方依据：encoding/json.Marshal](https://pkg.go.dev/encoding/json#Marshal)。

nil 与空还不是“是否占用了独立内存块”的可靠检测手段。实现可以共享某些零大小对象的存储，也可能优化掉分配；程序应依据 nil、长度与规定的操作行为判断，而不是猜测空切片的数据指针。

<a id="section-3-11-3"></a>

#### 3.11.3 切片的拷贝

“拷贝切片”至少有三种不同意思。先明确要分离到哪一层，再选择写法：

| 写法 | 复制了什么 | 哪些数据仍可能共享 |
| --- | --- | --- |
| `b := a` | 切片值中的描述信息 | 全部底层元素 |
| `copy(b, a)` | 两者当前长度覆盖范围内的元素值 | 取决于 `b` 的来源；元素引用的更深层对象也可能共享 |
| `b := slices.Clone(a)` | 当前可见元素的一份浅拷贝 | 元素内部的切片、map、指针所引用的对象 |
| 为每个内层对象另建存储并复制 | 显式递归处理的那些层 | 未处理的引用层，以及有意保留的共享关系 |

`copy` 本身不承诺让源、目标分离：如果 `b` 本来就是 `a` 的一个重叠区间，复制仍在同一个数组里发生。只有当目标确实来自独立存储时，才分离了这一层的元素。`slices.Clone` 的库契约明确说明元素按赋值方式复制，因此是浅拷贝。[官方依据：Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)、[slices.Clone](https://pkg.go.dev/slices#Clone)。

**二维切片要看两层。** 外层 `[][]int` 的每个元素本身又是一个 `[]int` 切片值。复制外层后，内层描述信息被复制，但各行的整数存储仍会共享。下面把“只复制外层”和“逐行再复制”放在同一个程序中比较。

```go
// 运行示例：R-03
package main

import (
	"fmt"
	"slices"
)

func cloneRows(src [][]int) [][]int {
	if src == nil {
		return nil
	}
	dst := make([][]int, len(src))
	for i, row := range src {
		dst[i] = slices.Clone(row)
	}
	return dst
}

func main() {
	original := [][]int{{1, 2}, {3, 4}}
	header := original
	shallow := slices.Clone(original)
	deep := cloneRows(original)

	shallow[0][0] = 9
	shallow[1] = []int{7, 8}

	fmt.Println("original:", original)
	fmt.Println("header:", header)
	fmt.Println("shallow:", shallow)
	fmt.Println("deep:", deep)
}
```

输出：

```text
original: [[9 2] [3 4]]
header: [[9 2] [3 4]]
shallow: [[9 2] [7 8]]
deep: [[1 2] [3 4]]
```

第一处写入 `shallow[0][0] = 9` 会沿着第一行的描述信息找到共享整数数组，因此 `original` 也看到了变化。第二处写入 `shallow[1] = []int{7, 8}` 替换的是 `shallow` 外层数组中的一个切片值；由于外层已经克隆，这个替换不会改变 `original[1]`。`deep` 在所有修改发生前逐行复制了整数，因此保持初始内容。

`cloneRows` 对 `[][]int` 已经分离了所有可修改的整数存储，还保留了外层及各行的 nil 状态。它不是适用于任意对象的通用深拷贝工具：遇到含指针的结构体、循环引用或需要保留的行间共享关系，必须先定义复制契约。即使是二维数据，按行复制也会打破原来不同切片之间可能存在的行内共享；这可能正是需求，也可能不是。

**限制容量不会自动复制。** `slices.Clip(s)` 的语义是返回 `s[:len(s):len(s)]`。它使后续追加无法使用当前长度之后的容量，但已有元素仍然共享。若需要保存一份独立的小结果，应考虑克隆所需元素，而不是只调用 `Clip`。[官方依据：slices.Clip](https://pkg.go.dev/slices#Clip)。

```go
// 运行示例：R-04
package main

import (
	"fmt"
	"slices"
)

func main() {
	base := []int{10, 20, 30, 40}
	window := base[1:3]
	clipped := slices.Clip(window)
	detached := slices.Clone(window)

	clipped[0] = 200
	detached[1] = 300

	fmt.Println("base:", base)
	fmt.Println("clipped:", clipped)
	fmt.Println("detached:", detached)
	fmt.Println("clipped length and capacity:", len(clipped), cap(clipped))
}
```

输出：

```text
base: [10 200 30 40]
clipped: [200 30]
detached: [20 300]
clipped length and capacity: 2 2
```

当一个很大的字节切片只需要保留其中几十个字节时，长期保存它的子切片可能使原来的大数组继续可达。克隆那几十个字节，并让所有指向原数组的引用结束，才有机会不再保留原数组。什么时候回收由运行时决定；给某一个切片变量赋 nil，也不会使其他变量正在引用的数组失效。官方博客专门讨论了这种“小片段保留大数组”的情况。[官方依据：Go Slices: usage and internals](https://go.dev/blog/slices-intro)、[A Guide to the Go Garbage Collector](https://go.dev/doc/gc-guide)。

**切片转数组，也要区分值与指针。** `[N]T(s)` 产生数组值并复制前 `N` 个元素；`(*[N]T)(s)` 产生指向切片对应元素的数组指针，继续共享底层存储。前者从 Go 1.20 起支持，后者从 Go 1.17 起支持。两种转换都要求 `len(s) >= N`，不满足会在运行时 panic；只有容量足够、长度不足也不行。[官方依据：Conversions from slice to array or array pointer](https://go.dev/ref/spec#Conversions_from_slice_to_array_or_array_pointer)。

```go
// 运行示例：R-05
package main

import "fmt"

func main() {
	s := []int{1, 2, 3, 4}
	value := [3]int(s)
	view := (*[3]int)(s)

	s[0] = 9
	value[1] = 8
	view[2] = 7

	fmt.Println("array value:", value)
	fmt.Println("slice:", s)
	fmt.Println("array pointer contents:", *view)
}
```

输出：

```text
array value: [1 8 3]
slice: [9 2 7 4]
array pointer contents: [9 2 7]
```

这里 `value` 的整数元素独立，`view` 则仍然能写入 `s` 的前三个元素。这种区别来自转换结果的类型，不能简单概括为“转成数组都会复制”或“转换只改变看法”。如果元素本身含引用，数组值转换仍只按元素值复制，和本节前面的浅拷贝原则一致。

<a id="section-3-11-4"></a>

#### 3.11.4 切片的扩容机制

**先记语言保证，再阅读实现。** 当 `append` 所需的新长度不超过原容量时，它复用原来的底层数组；容量不足时，它安排足够容纳旧元素和新增元素的新底层数组，并返回更新后的切片。规范没有承诺新容量必须是旧容量的某个倍数。因此，“是否继续共享”可以依照容量是否足够推导，“下一次容量一定是多少”通常不能当作跨版本规则。[官方依据：Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)。

下面的源码分析限定为**本次实际使用的 Go 1.27.3 工具链**。在线源码页面会随版本更新；复现时可在对应工具链安装目录中查看 `src/runtime/slice.go`、`src/runtime/msize.go` 和 `src/internal/runtime/gc/sizeclasses.go`。源码中还存在编译器配合的优化路径，不应据此断言每一个 `append` 都必须经过完全相同的一次函数调用。

**常见的扩容路径分成三个层次：**

1. 先由 `nextslicecap` 根据所需新长度与旧容量计算候选容量。
2. 再根据元素大小换算字节数，按内存分配器规则取整，并换回实际可容纳的元素数。含指针元素还涉及相应的分配和垃圾回收处理。
3. 准备新的存储，复制旧的有效元素，形成新的切片值；追加调用方随后完成新增元素的写入。

这段描述概括源码职责，不是新的语言契约。特别是，`growslice` 负责扩展存储及保留原数据，不能把“所有新增参数都由这个函数自己写入”也当作它的工作。[源码依据：runtime/slice.go](https://go.dev/src/runtime/slice.go)、[runtime/msize.go](https://go.dev/src/runtime/msize.go)。

**第一层：候选容量怎样计算。** 下列 `candidateCapacity` 保留本次工具链 `nextslicecap` 的计算步骤和溢出分支，仅改函数名、加入中文说明并补上演示入口。它用于解释算法，不是让业务代码自行替代 `append`；也不是任意负数和任意整数输入都适用的公共函数。演示输入均满足“原容量非负、所需长度大于原容量”的扩容前提。

```go
// 运行示例：R-06
// candidateCapacity 改编自 Go 1.27.3 runtime/slice.go 的 nextslicecap。
// Copyright 2009 The Go Authors. All rights reserved.
// 原始代码采用 BSD 许可，完整许可见本笔记附录 C。
package main

import "fmt"

func candidateCapacity(newLen, oldCap int) int {
	newcap := oldCap
	doublecap := newcap + newcap
	if newLen > doublecap {
		return newLen
	}

	const threshold = 256
	if oldCap < threshold {
		return doublecap
	}
	for {
		newcap += (newcap + 3*threshold) >> 2
		// 与原实现一样，同时处理达到所需长度及整数溢出的情形。
		if uint(newcap) >= uint(newLen) {
			break
		}
	}
	if newcap <= 0 {
		return newLen
	}
	return newcap
}

func main() {
	cases := [][2]int{
		{0, 1},
		{10, 11},
		{256, 257},
		{300, 301},
		{512, 513},
		{1024, 1025},
		{10, 40},
	}
	for _, item := range cases {
		oldCap, newLen := item[0], item[1]
		fmt.Printf("old=%d need=%d candidate=%d\n",
			oldCap, newLen, candidateCapacity(newLen, oldCap))
	}
}
```

输出：

```text
old=0 need=1 candidate=1
old=10 need=11 candidate=20
old=256 need=257 candidate=512
old=300 need=301 candidate=567
old=512 need=513 candidate=832
old=1024 need=1025 candidate=1472
old=10 need=40 candidate=40
```

在未发生整数溢出的通常范围内，可以把这个版本的算法理解为：先判断本次所需长度是否超过旧容量的两倍；超过时，候选值直接取所需长度。否则，旧容量小于 256 的路径取两倍；达到该阈值后，使用下面的递增式，必要时重复直到候选容量足够：

```text
newcap = newcap + floor((newcap + 3 × 256) / 4)
```

所以它不是简单的“达到 256 后马上严格乘 1.25”。例如 `300 + floor((300 + 768) / 4) = 567`，这一轮显然不等于 `300 × 1.25`。在较大的容量上，常数项的相对影响变小，增长倍率才趋近 1.25。代码中的无符号比较与后续检查用于处理整数溢出边界，不能随手删掉后宣称与运行时实现完全相同。[源码依据：nextslicecap](https://go.dev/src/runtime/slice.go)。

**第二层：候选值不一定等于最后观察到的 `cap`。** 下面执行真正的 `append`，并打印运行环境。由于容量数字取决于工具链、架构、元素类型和分配策略，这一段输出是本次环境的运行记录；在其他环境出现不同的容量数字并不自动表示程序错误。

```go
// 运行示例：R-07
// 本示例的具体容量输出是环境相关的实验记录。
package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Println(runtime.Version(), runtime.GOOS+"/"+runtime.GOARCH)
	for _, n := range []int{10, 256, 300, 512, 1024} {
		s := make([]int, n, n)
		s = append(s, 1)
		fmt.Printf("old=%d len=%d actual=%d\n", n, len(s), cap(s))
	}
}
```

本次验证环境中的输出：

```text
go1.27.3 linux/amd64
old=10 len=11 actual=20
old=256 len=257 actual=512
old=300 len=301 actual=608
old=512 len=513 actual=848
old=1024 len=1025 actual=1536
```

以旧容量 300 这一行解释：候选容量为 567；该环境下 `int` 占 8 字节，因此候选元素存储需要 `567 × 8 = 4536` 字节。对应分配路径把字节数取整到可用的 4864 字节级别，换算回来就得到 `4864 / 8 = 608` 个 `int` 的容量。这里多出来的位置来自分配器取整，不是语言规范另加了一条“300 必须变成 608”的规则。[源码依据：roundupsize](https://go.dev/src/runtime/msize.go)、[内存大小类别表](https://go.dev/src/internal/runtime/gc/sizeclasses.go)。

进一步检查实现时，还需要留意三个边界。一次追加很多元素可能直接跳过通常的增长阶段；不同元素大小与是否包含指针，可能进入不同的计算、分配与清零路径；零大小元素有自己的处理分支。学习基础用法时，不需要背下所有分支，但应避免把一次 `[]int` 实验的数字套用到所有切片上。

**第三层：新旧存储如何影响已有引用。** 扩容会把原来有效元素的值复制过去，但不会把其他切片变量里的描述信息一起改写。仍然引用旧数组的切片或旧元素指针，继续访问旧数组；它们不会自动“跟随”新切片。若元素是指针、map 或另一个切片，元素值的复制仍可能让新旧数组间接引用同一个更深层对象。这就是“扩容分离了外层存储”与“所有对象都完全独立”的区别。[官方依据：Arrays, slices (and strings): The mechanics of append](https://go.dev/blog/slices)、[Slice types](https://go.dev/ref/spec#Slice_types)。

**怎样把这些知识用到代码中。** 已知大致数量时，可以用 `make([]T, 0, expected)` 预留容量；已有切片需要准备额外空间时，可以使用 `slices.Grow`。`Grow(s, n)` 保证返回值至少还能追加 `n` 个元素而不再为这次额度分配新的底层空间，同时保持原长度和当前元素。它可能换存储，所以同样需要接收返回值；它也没有承诺某一个精确容量。[官方依据：slices.Grow](https://pkg.go.dev/slices#Grow)。

```go
// 运行示例：R-08
package main

import (
	"fmt"
	"slices"
)

func main() {
	original := []int{1, 2}
	grown := slices.Grow(original, 3)
	fmt.Println("length stays:", len(grown))
	fmt.Println("room for three:", cap(grown)-len(grown) >= 3)
	grown = append(grown, 3, 4, 5)
	fmt.Println("grown:", grown)
	fmt.Println("original:", original)
}
```

输出：

```text
length stays: 2
room for three: true
grown: [1 2 3 4 5]
original: [1 2]
```

这个程序检查的是 `Grow` 文档承诺的“剩余容量至少够用”，因此不需要把某个实际容量写死在输出里。过度预留同样会增加存储占用；数量不清楚时，直接追加往往已经足够清楚。只有在实际测量确认相关分配成为问题后，再围绕具体工作负载调整容量策略。理解扩容机制的主要收益，是知道哪些行为能依赖、哪些数字需要注明环境。

### A.1 先问四个问题，再判断代码

遇到数组或切片代码时，先依次问：**这是数组值还是切片值？当前长度和容量是多少？哪些元素仍然共享？这个操作有没有返回需要保存的新切片？** 大多数“为什么原来的数据也变了”“为什么追加以后调用方没变化”的问题，都可以顺着这四个问题解释。

下表只概括正文已经解释的操作；遇到元素含切片、map、指针时，还要继续检查更深层的共享关系。[规则入口：Go 语言规范](https://go.dev/ref/spec)、[slices 标准库](https://pkg.go.dev/slices)。

| 操作 | 当前层元素是否被复制或修改 | 是否应接收结果 | 需要记住的边界 |
| --- | --- | --- | --- |
| `b := array` | 复制整个数组值 | 保存赋值结果 | 引用类元素的目标对象不会递归复制 |
| `b := slice` | 只复制切片值；元素仍共享 | 保存赋值结果 | 两个变量各自保存长度和容量 |
| `s[i] = v` | 修改共享存储中的一个元素 | 无返回值 | 索引必须小于 `len(s)` |
| `s[low:high]` | 建立共享视图 | 需要使用返回的切片 | 切片的 `high` 可到 `cap(s)`，不能把它与索引上界混淆 |
| `s[low:high:max]` | 建立共享视图并限制容量 | 需要使用返回的切片 | 容量为 `max-low`；已有元素仍共享 |
| `append(s, values...)` | 写入追加元素；必要时复制到新数组 | 通常必须保存返回切片 | 旧变量不会自动获得新长度、新存储 |
| `copy(dst, src)` | 向现有目标元素写入 | 需要时接收复制数量 | 复制数取两者当前长度的较小值；允许重叠 |
| `slices.Clone(s)` | 复制可见元素，浅拷贝 | 是 | 保留 nil 状态；不承诺精确容量 |
| `slices.Clip(s)` | 不复制元素，只把容量限制为长度 | 是 | 不会把大数组的小视图自动迁移到小数组 |
| `slices.Grow(s, n)` | 必要时准备额外存储 | 是 | 长度不变；保证至少还能追加 `n` 个元素 |
| `slices.Sort(s)` | 原地重新排列元素 | 无切片返回值 | 共享别名也会看到排序结果 |
| `slices.Compact(s)` | 原地合并相邻相等项 | 是 | 去除全部重复值前通常需要先排序，或换用保序方案 |
| `slices.Delete(s, i, j)` | 原地移动元素并缩短结果 | 是 | 删除半开区间 `[i,j)`；Go 1.22+ 清零废弃尾部 |
| `clear(s)` | 把当前长度内元素置零 | 无返回值 | 不改变长度、容量，也不覆盖长度之外的全部容量 |
| `s = s[:0]` | 不清除原元素，只把当前长度置零 | 通过赋值保存 | 容量和存储引用通常保留 |
| `s = nil` | 改变当前变量的切片值 | 通过赋值保存 | 其他仍然存在的引用不受影响 |

### A.3 参考答案与定位

**1．数组长度参与类型。** `[3]int`、`[4]int` 和 `[]int` 是三种不同类型。前两者是不同长度的数组，第三种是切片。需要接受不同长度时，可以将参数设计为 `[]int`，但这也意味着函数收到的切片可能共享调用方元素，接口约定应说明是否修改。见 2.1、2.6、3.9。[规范：Array types](https://go.dev/ref/spec#Array_types)。

**2．空内容与 nil 状态不是同一个判断。** `a` 为长度 0、容量 0、nil，JSON 为 `null`；`b` 为长度 0、容量 0、非 nil，JSON 为 `[]`；`c` 为长度 0、容量 4、非 nil，JSON 为 `[]`。这里比较的是整个 `[]int`，没有结构体字段标签的影响。见 R-02。[文档：json.Marshal](https://pkg.go.dev/encoding/json#Marshal)。

**3．每次切片都以当前视图为起点。** `s` 为 `[2 3 4]`，长度 3、容量 5；`t` 为 `[3]`，长度 1、容量 4。`t[0]` 对应原数组 `a[2]`，所以修改后 `a` 为 `[1 2 99 4 5 6]`。见 S-14 和 3.11.1 的共享关系表。[规范：Slice expressions](https://go.dev/ref/spec#Slice_expressions)。

**4．长度表示已经存在的元素。** `make([]int, 3)` 先得到三个零值元素；追加 7 后得到 `[0 0 0 7]`。如果准备从空结果逐次收集，应写 `make([]int, 0, 3)`；如果已经创建长度 3，则应在有效索引位置赋值。见 3.3.1。[规范：Making slices, maps and channels](https://go.dev/ref/spec#Making_slices_maps_and_channels)。

**5．容量是否足够决定这次追加的共享结果。** 第一种写法中，`a` 为 `[1 2 9 4]`，`s` 为 `[1 2]`，`t` 为 `[1 2 9]`；`s` 仍保存长度 2，但追加已经覆盖共享数组的第三个位置。三下标写法把 `s` 容量设为 2，追加需要新数组，因此 `a` 保持 `[1 2 3 4]`，`s` 为 `[1 2]`，`t` 为 `[1 2 9]`。见 S-15、T-01、T-02。[规范：Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)。

**6．传入函数的是切片值的一份副本。** 元素写入会沿着副本中的引用访问共享存储；对局部参数重新赋值，只更新函数内保存的长度、容量和存储引用。需要把追加后的结果交回调用方时，常用 `func add(s []int) []int`，调用方写成 `s = add(s)`。追加还可能写入旧数组的隐藏容量，不能把“长度没变”误当成“任何存储都没变”。见 T-03。[官方博客：The mechanics of append](https://go.dev/blog/slices)。

**7．返回 0。** `copy` 依据的是 `len(dst)`，不是 `cap(dst)`。可以直接 `dst := make([]int, len(src)); copy(dst, src)`；也可以确认容量足够后先把 `dst` 重切到 `len(src)` 再复制；只需要一份浅拷贝时，可以用 `slices.Clone(src)`。不同方案是否保留 nil 状态，应按接口需求选择。见 S-11、S-13。[规范：Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)。

**8．写入行元素会共享，替换外层元素不共享。** 第一条把 `a[0][0]` 也改成 9；第二条只替换 `b` 外层数组的第二个元素，`a[1]` 仍为 `[3 4]`。逐行克隆才能分离这里的整数存储。见 R-03。[文档：slices.Clone](https://pkg.go.dev/slices#Clone)。

**9．不能通过增加副本修改原整数。** `v` 得到当前元素值的副本，修改原元素应使用索引，例如 `for i := range s { s[i]++ }`。对切片的 range 根据开始遍历时的切片长度确定索引范围，不会因局部变量 `s` 后续追加而无限扩展；但仍需区分共享元素在读取前发生的变化，以及数组值 range 的另一种行为。见 A-06、S-07、S-08。[规范：For statements with range clause](https://go.dev/ref/spec#For_statements)。

**10．`Compact` 只压缩相邻相等项。** 两个 1 被 2 隔开，直接调用不会合并它们。排序后压缩能得到全局唯一值，但会改变顺序；要保留首次出现的顺序，可用 map 记录已见值，并按输入顺序向新切片追加第一次出现的值。见 T-08、T-09。[文档：slices.Compact](https://pkg.go.dev/slices#Compact)。

**11．不能。** `Clip` 等价于限制容量的三下标切片操作，已有元素仍引用原存储。对所需非空整数或字节片段执行 `slices.Clone`，并让其他指向原数组的引用结束，才有机会不再保留大数组；如果元素本身含引用，还要评估是否需要复制更深层。回收时间不是 `Clone` 的即时承诺。见 R-04。[官方博客：Go Slices: usage and internals](https://go.dev/blog/slices-intro)。

**12．计算发生在不同阶段。** 567 是这一版本算法给出的候选元素数；在示例环境中换成字节后经分配器取整，得到可容纳 608 个 `int` 的存储。业务代码应依赖返回切片能够容纳所有元素、容量不小于长度，以及容量足够时复用原数组等规范保证；不要依赖跨版本不变的增长倍率或具体容量数字。见 R-06、R-07。[规范：Appending and copying slices](https://go.dev/ref/spec#Appending_and_copying_slices)、[源码：runtime/slice.go](https://go.dev/src/runtime/slice.go)。
